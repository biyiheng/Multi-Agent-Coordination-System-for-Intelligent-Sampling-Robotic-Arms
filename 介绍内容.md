## 🇨🇳 中文介绍

### 项目概述

**智能采样机械臂系统**是一套面向工业自动化场景的六自由度机械臂综合控制平台，运行于 Raspberry Pi（树莓派）之上，通过 STM32 微控制器驱动六路舵机，并集成 OpenMV 视觉模组实现目标检测与定位。系统采用异步事件驱动架构，支持 Docker 容器化部署与 systemd 服务管理，具备从运动规划、力控抓取到云端同步的完整能力链路。

- **版本**: v2.2.0
- **技术栈**: Python 3.11+ / FastAPI / WebSocket / SQLite / Docker / STM32 / OpenMV
- **运行平台**: Raspberry Pi OS (64-bit) / Linux / Windows (仿真模式)
- **许可证**: MIT

### 核心亮点

#### 1. 多智能体协同架构
系统采用 LangGraph 启发的状态机设计，由 `Orchestrator`（编排器）统一调度五大专业智能体：

| 智能体 | 职责 |
|--------|------|
| **Sampling Agent** | 采样任务规划与执行策略生成 |
| **Vision Agent** | OpenMV 图像采集、目标检测与位姿估计 |
| **Motion Agent** | 运动规划、轨迹生成与逆运动学求解 |
| **Quality Agent** | 抓取质量评估与任务完成度判定 |
| **Safety Agent** | 实时安全监控、碰撞预警与紧急停止 |

状态机覆盖 12 种状态（`IDLE → PLANNING → APPROACHING → DETECTING → GRASPING → LIFTING → INSPECTING → PLACING → EVALUATING → DONE`），并包含 `RECOVERY`（故障恢复）与 `ABORT`（紧急中止）两条异常处理路径，确保任务执行的鲁棒性。

#### 2. 循环工程 (Loop Engineering) 持续优化框架
独创的 **Loop Engineering** 方法论实现了"提出变更 → 执行 → 评估 → 保留最优"的自动化闭环优化：

- **Profiler（性能分析器）**: 实时检测慢操作，识别性能瓶颈（阈值 100ms）
- **Evaluator（七维评估器）**: 从延迟、可靠性、质量、效率、鲁棒性、上下文健康度、技能复用性七个维度量化系统表现
- **Context Manager（上下文管理器）**: 自动压缩超长上下文，防止状态衰减
- **Skill Extractor（技能提取器）**: 挖掘高频复用模式，自动沉淀为可复用技能
- **Knowledge Inheritor（知识继承器）**: 跨版本知识迁移，淘汰失效知识（衰减阈值 0.3）
- **Meta-Optimizer（元优化器）**: 演化策略优化，持续逼近最优配置

#### 3. 力位混合控制与柔顺抓取
基于 Hogan 阻抗控制理论与 Siciliano 力控框架，实现了完整的力控子系统：

- **导纳控制 (Admittance Control)**: 力→位置修正，适用于精密装配
- **阻抗控制 (Impedance Control)**: 位置→力响应，保障接触安全
- **力位混合控制 (Hybrid Force/Position Control)**: 笛卡尔空间力位解耦
- **柔顺抓取策略**: 自适应夹持力控制、滑移检测、真空吸盘力控
- **末端执行器管理**: 快换装置支持、自动 TCP 标定（SVD 刚性变换）

#### 4. 全方位安全防护
- 工作空间边界约束与实时超限检测
- AABB 碰撞检测 + 自碰撞检测（非相邻连杆最小距离）
- 安全撤退路径自动生成
- 紧急停止（ESTOP）三级响应机制（OK → DANGER → ESTOP）
- 看门狗定时器（50ms 间隔）
- 安全状态去抖动（防抖间隔 100ms），避免冗余检查

#### 5. 运动学与轨迹规划
- **正运动学 (FK)**: 基于改进 DH 参数的齐次变换矩阵链式求解
- **逆运动学 (IK)**: Pieper 几何方法 + 多解排序（最小关节位移优先）
- **雅可比矩阵**: 数值雅可比 + 奇异值分解 (SVD) 阻尼伪逆
- **轨迹规划**: 五次多项式插值、S 形速度曲线、梯形速度曲线、路径平滑
- **工作空间分析**: 蒙特卡洛边界计算、可达性检查、灵巧度/可操作度分析

#### 6. 完善的测试与质量保障
- **130+ 测试用例**，100% 通过率
- 覆盖：运动学、轨迹规划、碰撞检测、工作空间分析、力控制、API 接口、安全扫描、性能基准
- 硬件仿真模式：无需物理硬件即可运行完整测试套件
- 支持 pytest、pytest-asyncio、pytest-cov 覆盖率统计

#### 7. Docker 容器化部署
- 多阶段 Docker 构建，最小化镜像体积
- docker-compose 一键启动（主控 + 数据库）
- 支持 2GB 内存树莓派的资源限制配置
- 国内镜像加速器配置指南

#### 8. Web 远程控制面板

### 问题处理专项

在开发与自检过程中，系统性地发现并修复了 **10 项关键 Bug**，涵盖运行时崩溃、数据一致性、并发安全、数值精度等维度：

#### 🔴 Critical（严重）
| 问题 | 根因 | 解决方案 |
|------|------|----------|
| **WebSocket 遥测崩溃** — `TelemetryStream` 引用了 `WebSocketManager` 不存在的 `active_connections` 属性 | 模块间接口不同步，两模块由不同阶段开发 | 统一使用 `client_count` 属性替代，修复 2 处引用 |

#### 🟡 Medium（中等）
| 问题 | 根因 | 解决方案 |
|------|------|----------|
| **API joint_id 范围不一致** — 部分接口使用 1-6，部分使用 0-5 | 索引约定未统一 | 全局统一为 0-5（代码内部索引），API 层自动转换 |
| **数据库路径不一致** — 配置与实际路径不匹配 | 重构后路径未同步更新 | 统一 `sqlite:///./data/sampling.db` |
| **IK 不可达点检测被掩盖** — clamping 操作覆盖了不可达判断 | 异常处理逻辑顺序错误 | 先检测不可达，再执行 clamping |
| **浮点循环累积误差** — 碰撞检测中使用浮点数作为循环变量 | 浮点精度限制 | 改用整数循环，循环体内计算浮点值 |
| **atan2 归一化 O(n) 复杂度** — 使用 while 循环归一化角度 | 算法选择不当 | 使用 `atan2(sin(θ), cos(θ))` 单次 O(1) 归一化 |
| **deque 替代 list** — 错误历史截断需要 O(n) 切片 | 数据结构选择不当 | 使用 `collections.deque(maxlen=...)` 实现 O(1) 自动截断 |
| **asyncio.Lock 线程安全** — `ErrorNotifier` 共享状态存在竞态条件 | 并发访问未保护 | 添加 `asyncio.Lock` 保护所有共享状态 |
| **协议检测死锁风险** — 协议自动检测在持有锁时执行 | 临界区范围过大 | 将协议检测逻辑移到锁外执行 |
| **CancelledError 被吞没** — 重试装饰器捕获 Exception 时吞没了取消信号 | 异常捕获粒度过粗 | 显式检查并重新抛出 `asyncio.CancelledError` |

## 🇬🇧 English Introduction

### Project Overview

The **Intelligent Sampling Robotic Arm System** is a comprehensive 6-DOF robotic arm control platform designed for industrial automation scenarios. Running on a Raspberry Pi, it drives six servo motors through an STM32 microcontroller and integrates an OpenMV vision module for target detection and localization. The system features an asynchronous event-driven architecture with Docker containerization and systemd service management, delivering a complete capability chain from motion planning and force-controlled grasping to cloud synchronization.

- **Version**: v2.2.0
- **Tech Stack**: Python 3.11+ / FastAPI / WebSocket / SQLite / Docker / STM32 / OpenMV
- **Target Platform**: Raspberry Pi OS (64-bit) / Linux / Windows (simulation mode)
- **License**: MIT

### Key Highlights

#### 1. Multi-Agent Collaborative Architecture
Built on a LangGraph-inspired state machine design, the `Orchestrator` coordinates five specialized agents:

| Agent | Responsibility |
|-------|---------------|
| **Sampling Agent** | Task planning and execution strategy generation |
| **Vision Agent** | OpenMV image acquisition, target detection, and pose estimation |
| **Motion Agent** | Motion planning, trajectory generation, and inverse kinematics |
| **Quality Agent** | Grasp quality assessment and task completion evaluation |
| **Safety Agent** | Real-time safety monitoring, collision warning, and emergency stop |

The state machine spans 12 states (`IDLE → PLANNING → APPROACHING → DETECTING → GRASPING → LIFTING → INSPECTING → PLACING → EVALUATING → DONE`) with two fault-handling paths (`RECOVERY` and `ABORT`), ensuring robust task execution under all conditions.

#### 2. Loop Engineering — Continuous Optimization Framework
An innovative **Loop Engineering** methodology that automates the "propose change → execute → evaluate → retain best" closed-loop optimization:

- **Profiler**: Real-time slow operation detection, identifying performance bottlenecks (threshold: 100ms)
- **Evaluator (7-Dimensional)**: Quantifies system performance across latency, reliability, quality, efficiency, robustness, context health, and skill reusability
- **Context Manager**: Automatically compresses oversized contexts, preventing state decay
- **Skill Extractor**: Mines high-frequency reuse patterns, distilling them into reusable skills
- **Knowledge Inheritor**: Cross-version knowledge transfer with decay-based obsolescence pruning (threshold: 0.3)
- **Meta-Optimizer**: Evolutionary strategy optimization, continuously converging toward optimal configurations

#### 3. Hybrid Force/Position Control & Compliant Grasping
Based on Hogan's impedance control theory and Siciliano's force control framework, a complete force control subsystem is implemented:

- **Admittance Control**: Force → position correction, ideal for precision assembly
- **Impedance Control**: Position → force response, ensuring safe contact
- **Hybrid Force/Position Control**: Decoupled force-position control in Cartesian space
- **Compliant Grasping**: Adaptive grip force, slip detection, vacuum suction cup force control
- **End-Effector Management**: Quick-change tool system, automatic TCP calibration (SVD rigid transformation)

#### 4. Comprehensive Safety Protection
- Workspace boundary constraints with real-time limit checking
- AABB collision detection + self-collision detection (minimum distance between non-adjacent links)
- Automatic safe retreat path generation
- Three-tier emergency stop (ESTOP) response: OK → DANGER → ESTOP
- Watchdog timer (50ms interval)
- Safety state debouncing (100ms interval), preventing redundant checks

#### 5. Kinematics & Trajectory Planning
- **Forward Kinematics (FK)**: Chain-based homogeneous transformation using modified DH parameters
- **Inverse Kinematics (IK)**: Pieper geometric method with multi-solution ranking (minimum joint displacement)
- **Jacobian**: Numerical Jacobian with SVD damped pseudo-inverse
- **Trajectory Planning**: Quintic polynomial interpolation, S-curve velocity profiles, trapezoidal velocity profiles, and path smoothing
- **Workspace Analysis**: Monte Carlo boundary computation, reachability checks, dexterity/manipulability analysis

#### 6. Robust Testing & Quality Assurance
- **130+ test cases** with 100% pass rate
- Coverage: kinematics, trajectory planning, collision detection, workspace analysis, force control, API endpoints, security scanning, performance benchmarks
- Hardware simulation mode: run full test suites without physical hardware
- Supports pytest, pytest-asyncio, and pytest-cov for coverage statistics

#### 7. Docker Containerized Deployment
- Multi-stage Docker builds for minimal image size
- One-command startup via docker-compose (controller + database)
- Resource limit configuration for 2GB Raspberry Pi
- China mirror accelerator configuration guide included

#### 8. Web Remote Control Dashboard
- FastAPI RESTful API (`/api/health`, `/api/status`, `/api/emergency_stop`, `/api/home`)
- WebSocket real-time telemetry streaming (joint angles, sensor data, system status)
- Auto-generated Swagger UI interactive documentation (`/docs`)
- CORS cross-origin support

### Problem Resolution

During development and self-inspection, **10 critical bugs** were systematically identified and resolved across runtime stability, data consistency, concurrency safety, and numerical precision:

#### 🔴 Critical
| Issue | Root Cause | Resolution |
|-------|-----------|------------|
| **WebSocket Telemetry Crash** — `TelemetryStream` referenced `active_connections`, a non-existent attribute on `WebSocketManager` | Interface mismatch between modules developed in different phases | Unified to use `client_count` attribute, fixed 2 references |

#### 🟡 Medium
| Issue | Root Cause | Resolution |
|-------|-----------|------------|
| **API joint_id Range Inconsistency** — Some endpoints used 1-6, others used 0-5 | Index convention not standardized | Globally unified to 0-5 (internal), with auto-conversion at API layer |
| **Database Path Inconsistency** — Configuration and actual paths mismatched | Path not synced after refactoring | Unified to `sqlite:///./data/sampling.db` |
| **IK Unreachable Point Detection Masked** — Clamping overrode unreachability flag | Incorrect exception handling order | Detect unreachability first, then apply clamping |
| **Float Loop Accumulation Error** — Floating-point used as loop variable in collision detection | FP precision limitations | Switched to integer loop with FP computation inside |
| **atan2 Normalization O(n) Complexity** — while-loop used for angle normalization | Suboptimal algorithm choice | Single-shot `atan2(sin(θ), cos(θ))` O(1) normalization |
| **deque Replacement for list** — Error history truncation required O(n) slicing | Suboptimal data structure | Used `collections.deque(maxlen=...)` for O(1) auto-truncation |
| **asyncio.Lock Thread Safety** — Race condition in `ErrorNotifier` shared state | Unprotected concurrent access | Added `asyncio.Lock` to guard all shared state |
| **Protocol Detection Deadlock Risk** — Protocol auto-detection executed while holding lock | Overly broad critical section | Moved detection logic outside the lock |
| **CancelledError Swallowed** — Retry decorator's `except Exception` swallowed cancellation signals | Overly coarse exception granularity | Explicitly check and re-raise `asyncio.CancelledError` |
