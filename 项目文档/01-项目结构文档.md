## 1. 项目概述

本系统基于STM32F103C8T6（实时控制）、OpenMV H7 Plus（视觉处理）和 Raspberry Pi（高层决策）三大硬件平台，构建集感知、决策、调度、执行与反馈于一体的智能采样机械臂系统。系统采用多智能体协同架构，支持多色物体检测追踪、AprilTag位姿估计、视觉质量检测、6-DOF运动学控制、轨迹规划、微信小程序远程操控，并新增 Android/iOS 双端 App（Flutter）与 ESP32 WiFi 模块，实现多端（App/小程序/Web/硬件）数据互通与统一账号体系。

**核心特性：**
- 5层架构：感知层、决策层、调度层、执行层、反馈层
- 多智能体协同：Sampling、Vision、Motion、Quality、Safety 五大Agent
- 3种采样策略：Grid（网格）、Adaptive（自适应）、Targeted（定点）
- 多层安全体系：硬件级、固件级、软件级三级防护
- 实时遥测：WebSocket双向通信，延迟<100ms
- 多端互通：Android/iOS App、微信小程序、Web、硬件通过统一账号体系、设备中心与 WebSocket 中枢（/ws/hub）数据互通
- WiFi 配网：ESP32 模块（STA/AP/扫描）配网与状态持久化，App/小程序可直接配置

## 4. 数据流架构

### 4.1 主要数据流路径

```
                          采样任务生命周期数据流
                          ========================

  1. 用户发起任务
     微信小程序 ──[HTTPS POST /api/tasks]──► RPi FastAPI
                                                    │
  2. 任务分解                                        │
     RPi Orchestrator ──► SamplingAgent ──► 生成采样点序列
                                                    │
  3. 视觉定位                                        │
     RPi VisionAgent ──[UART1]──► STM32 ──[UART2]──► OpenMV
     OpenMV 执行颜色检测/AprilTag ──[UART2]──► STM32 ──[UART1]──► RPi
                                                    │
  4. 运动规划                                        │
     RPi MotionAgent ──► Kinematics.solve_ik() ──► 关节角度序列
     TrajectoryPlanner.plan() ──► 时间-角度插值表
                                                    │
  5. 执行                                            │
     RPi ──[UART1: #ARM:J0,1500,J1,1200,...!]──► STM32
     STM32 ──[UART3: #000P1500T1000!]──► 舵机ID0
     STM32 ──[UART3: #001P1200T1000!]──► 舵机ID1
     ... (6个舵机依次发送)
                                                    │
  6. 反馈                                            │
     STM32 ──[UART1: #STATE:OK!]──► RPi
     RPi ──[WebSocket]──► 微信小程序 (实时状态更新)
```

### 4.2 UART 数据帧格式

**RPi ↔ STM32 (UART1, PA9/PA10, 115200-8-N-1):**

```
命令格式:  #<CMD>:<PARAM1>,<PARAM2>,...,<PARAMN>!
响应格式:  #<CMD>:<STATUS>,<DATA1>,...,<DATAN>!

示例:
  发送: #ARM:J0,1500,J1,1200,J2,2000,J3,1500,J4,1500,J5,1000!
  响应: #ARM:OK!
  发送: #STATUS:?
  响应: #STATUS:IDLE, J0=1500, J1=1200, J2=2000, J3=1500, J4=1500, J5=1000!
```

**STM32 ↔ OpenMV (UART2, PA2/PA3, 115200-8-N-1):**

```
命令格式:  #<CMD>!
响应格式:  #<CMD>:<DATA_JSON>!

示例:
  发送: #color_tracing!
  响应: #color_tracing:{"red": [[120,80],[150,90]], "blue": [[200,60]]}!
  发送: #apriltag_sorting!
  响应: #apriltag_sorting:{"id":0,"x":150,"y":120,"z":300,"rx":0.1,"ry":0.2,"rz":0.1}!
```

**STM32 → 总线舵机链 (UART3, PB10/PB11, 115200-8-N-1):**

```
格式:  #<ID><POS><TIME>!
  ID:   3位十进制数 (000-254)
  POS:  4位十进制数 (0500-2500, PWM值)
  TIME: 4位十进制数 (0000-9999, 运动时间ms)

示例:
  #000P1500T1000!  →  ID0舵机, PWM=1500, 时间1000ms
  #001P2000T0500!  →  ID1舵机, PWM=2000, 时间500ms
  #005P1000T0000!  →  ID5舵机(夹爪), PWM=1000, 立即执行
```

## 6. 命名规范与代码组织原则

### 6.1 文件命名规范

| 层级 | 规范 | 示例 |
|------|------|------|
| STM32 驱动文件 | `y_<模块名>.c/h` | `y_bus_servo.c`, `y_delay.h` |
| STM32 应用文件 | `app_<模块名>.c/h` | `app_protocol.c`, `app_arm.h` |
| STM32 库文件 | `stm32f10x_<外设>.c/h` | `stm32f10x_usart.c` |
| OpenMV 模块 | `<功能>_<用途>.py` | `color_detection.py`, `uart_protocol.py` |
| RPi 模块 | `<功能>.py` 或 `<模块名>_<功能>.py` | `kinematics.py`, `stm32_comm.py` |
| RPi 配置文件 | `<名称>.yaml` | `arm_params.yaml` |
| 小程序页面 | 目录名=功能名, 文件=页面名.js/json/wxml/wxss | `pages/control/control.js` |
| 小程序组件 | 目录名=组件名, 文件=组件名.js/json/wxml/wxss | `components/joystick/joystick.js` |
| 文档文件 | `<序号>-<文档名>.md` | `01-项目结构文档.md` |

### 6.2 代码组织原则

**STM32 固件:**
- **分层架构**: CMSIS(核心) → Libraries(外设库) → SRC(驱动层) → USER(应用层)
- **驱动模块化**: 每个硬件外设封装为独立模块(.c/.h)
- **统一前缀**: 驱动层使用 `y_` 前缀, 应用层使用 `app_` 前缀
- **中断集中管理**: 所有ISR统一在 `stm32f10x_it.c` 中处理
- **配置集中**: 全局宏定义在 `main.h` 中, 外设选择在 `stm32f10x_conf.h` 中

**OpenMV 固件:**
- **模块化**: 视觉算法与通信分离
- **配置集中**: 所有阈值/参数在 `config.py` 中定义
- **命令模式**: 主循环接收命令, 通过 `command_handler.py` 分发

**树莓派控制系统:**
- **包组织**: 按功能域分包 (agents/, motion/, vision/, web/, ...)
- **配置外置**: 所有参数在 YAML 文件中, 代码中不硬编码
- **依赖注入**: Agent通过构造函数接收依赖, 便于测试
- **接口抽象**: 硬件通信层抽象为接口, 便于模拟测试
- **异步优先**: 使用 `asyncio` 和 FastAPI 异步特性

**微信小程序:**
- **页面组件化**: 复用UI封装为自定义组件
- **API封装**: 网络请求统一在 `utils/api.js` 和 `utils/ws.js` 中
- **数据驱动**: 使用 `setData` 进行数据绑定, 避免直接DOM操作

### 6.3 版本控制约定

- **主分支**: `main` — 稳定发布版本
- **开发分支**: `develop` — 日常开发
- **功能分支**: `feature/<模块名>` — 新功能开发
- **修复分支**: `fix/<问题描述>` — Bug修复
- **提交信息**: 中文描述, 格式 `[模块] 动作: 描述`
  - 示例: `[STM32] 新增: 总线舵机驱动模块`
  - 示例: `[RPi] 修复: 逆运动学多解选择逻辑`
