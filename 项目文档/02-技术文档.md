## 1. 系统架构概述

### 1.1 五层架构模型

系统采用分层架构设计，从底层传感器数据采集到顶层用户交互，共分为五层：

```
┌─────────────────────────────────────────────────────────────────────┐
│                  第5层: 反馈层 (Feedback Layer)                       │
│  微信小程序仪表盘 | WebSocket实时遥测 | 历史数据查询 | 告警通知       │
├─────────────────────────────────────────────────────────────────────┤
│                  第4层: 执行层 (Execution Layer)                      │
│  STM32 实时控制 | 舵机PWM驱动 | 动作组播放 | 传感器采集 | 紧急停止    │
├─────────────────────────────────────────────────────────────────────┤
│                  第3层: 调度层 (Scheduling Layer)                     │
│  多智能体编排器(LangGraph) | 任务分解 | 状态机流转 | 并发控制         │
├─────────────────────────────────────────────────────────────────────┤
│                  第2层: 决策层 (Decision Layer)                       │
│  采样策略选择 | 轨迹规划 | 逆运动学求解 | 碰撞检测 | 视觉引导         │
├─────────────────────────────────────────────────────────────────────┤
│                  第1层: 感知层 (Perception Layer)                     │
│  OpenMV 颜色检测 | AprilTag 6-DOF 位姿 | 质量检测 | 物体分类         │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.3 核心设计原则

| 原则 | 描述 | 实现方式 |
|------|------|---------|
| 硬实时优先 | 紧急停止 < 1ms 响应 | STM32 中断优先级 + 独立看门狗 |
| 故障安全 | 任何故障导致系统进入安全状态 | 多层安全：硬件限位 + 软件限位 + 看门狗 |
| 关注点分离 | 每层只处理自己的职责 | 五层架构 + 模块化设计 |
| 异步通信 | 非阻塞 I/O 最大化吞吐 | asyncio + UART DMA + WebSocket |
| 可观测性 | 所有状态可监控、可追溯 | 结构化日志 + 遥测数据 + 数据库 |
| 可扩展性 | 新功能通过增加 Agent 实现 | 插件式 Agent 架构 + 统一消息接口 |

## 3. 通信协议规范

### 3.1 RPi ↔ STM32 协议 (UART1)

**协议格式:**

```
通用帧格式:  #<CMD>:<PARAM1>,<PARAM2>,...,<PARAMN>!\r\n
响应帧格式:  #<CMD>:<STATUS>[,<DATA>]!\r\n
```

**帧字段说明:**

| 字段 | 说明 | 格式 |
|------|------|------|
| `#` | 帧起始符 | 固定字符 |
| `CMD` | 命令标识符 | 大写字母+数字 |
| `:` | 分隔符 | 固定字符 |
| `PARAM` | 参数列表 | 逗号分隔 |
| `!` | 帧结束符 | 固定字符 |
| `\r\n` | 换行符 | 可选 |

**命令分类表:**

| 类别 | 命令前缀 | 说明 | 示例 |
|------|---------|------|------|
| 机械臂控制 | `ARM` | 多关节同步控制 | `#ARM:J0,1500,J1,1200,J2,2000,J3,1500,J4,1500,J5,1000!` |
| 单关节控制 | `JNT` | 单个关节控制 | `#JNT:0,1500,1000!` |
| 动作组 | `ACT` | 播放预定义动作 | `#ACT:1!` |
| 状态查询 | `STATUS` | 查询当前状态 | `#STATUS:?!` |
| 紧急停止 | `ESTOP` | 立即停止所有运动 | `#ESTOP:!` |
| 归零 | `HOME` | 所有关节回零位 | `#HOME:!` |
| 速度设置 | `SPEED` | 设置全局速度系数 | `#SPEED:50!` |
| 加速度设置 | `ACC` | 设置加速度系数 | `#ACC:30!` |
| 视觉命令 | `VIS` | 转发视觉命令给OpenMV | `#VIS:color_tracing!` |
| 传感器读取 | `SENS` | 读取传感器数据 | `#SENS:0!` |
| 配置读写 | `CONF` | 读写配置参数 | `#CONF:WR,joint_limit_0_min,500!` |
| 心跳 | `PING` | 心跳检测 | `#PING:!` |
| 固件信息 | `INFO` | 查询固件版本 | `#INFO:?!` |

**响应状态码:**

| 状态 | 含义 |
|------|------|
| `OK` | 命令执行成功 |
| `ERR` | 命令执行失败 |
| `BUSY` | 系统正忙 |
| `ESTOP` | 系统处于紧急停止状态 |
| `LIMIT` | 关节超出限位 |
| `TIMEOUT` | 命令执行超时 |
| `IDLE` | 系统空闲 |
| `MOVING` | 机械臂运动中 |
| `HOMING` | 正在归零 |

**完整通信示例:**

```
RPi → STM32:  #ARM:J0,1500,J1,1200,J2,2000,J3,1500,J4,1500,J5,1000!\r\n
STM32 → RPi:  #ARM:OK!\r\n

RPi → STM32:  #STATUS:?!\r\n
STM32 → RPi:  #STATUS:IDLE,J0=1500,J1=1200,J2=2000,J3=1500,J4=1500,J5=1000!\r\n

RPi → STM32:  #ESTOP:!\r\n
STM32 → RPi:  #ESTOP:OK!\r\n

RPi → STM32:  #PING:!\r\n
STM32 → RPi:  #PING:PONG,1690000000!\r\n
```

## 4. 运动学模型

### 4.1 DH参数表

系统采用改进DH参数法（Modified DH Convention），定义如下：

| 关节 | a (mm) | α (deg) | d (mm) | θ (deg) | 关节范围 |
|------|--------|---------|--------|---------|---------|
| Joint 0 (底座) | 0 | 90 | 85 | θ₀ | -150° ~ +150° |
| Joint 1 (肩部) | 120 | 0 | 0 | θ₁ - 90 | -90° ~ +90° |
| Joint 2 (肘部) | 110 | 0 | 0 | θ₂ | -135° ~ +45° |
| Joint 3 (腕部俯仰) | 0 | 90 | 0 | θ₃ | -90° ~ +90° |
| Joint 4 (腕部旋转) | 0 | -90 | 95 | θ₄ | -180° ~ +180° |
| Joint 5 (夹爪) | 0 | 0 | 65 | θ₅ | 0° ~ +60° (开合) |

**坐标系定义:**
- 基座标系 {0}: 位于底座旋转中心, Z轴向上
- 世界坐标系 {W}: 与基座标系 {0} 重合
- 工具坐标系 {T}: 位于夹爪中心, Z轴沿夹爪方向

### 4.2 正向运动学

**齐次变换矩阵通式:**

$$T_i^{i-1} = \begin{bmatrix}
\cos\theta_i & -\sin\theta_i\cos\alpha_i & \sin\theta_i\sin\alpha_i & a_i\cos\theta_i \\
\sin\theta_i & \cos\theta_i\cos\alpha_i & -\cos\theta_i\sin\alpha_i & a_i\sin\theta_i \\
0 & \sin\alpha_i & \cos\alpha_i & d_i \\
0 & 0 & 0 & 1
\end{bmatrix}$$

**末端位姿计算:**

$$T_6^0 = T_1^0 \cdot T_2^1 \cdot T_3^2 \cdot T_4^3 \cdot T_5^4 \cdot T_6^5$$

**末端位置 (x, y, z):**

```
x = cos(θ₀) * [120*cos(θ₁-90) + 110*cos(θ₁-90+θ₂) + 95*cos(θ₁-90+θ₂+θ₃) + 65*cos(θ₁-90+θ₂+θ₃)*cos(θ₄)]
y = sin(θ₀) * [120*cos(θ₁-90) + 110*cos(θ₁-90+θ₂) + 95*cos(θ₁-90+θ₂+θ₃) + 65*cos(θ₁-90+θ₂+θ₃)*cos(θ₄)]
z = 85 + 120*sin(θ₁-90) + 110*sin(θ₁-90+θ₂) + 95*sin(θ₁-90+θ₂+θ₃) + 65*sin(θ₁-90+θ₂+θ₃)*sin(θ₄)
```

**末端姿态 (RPY欧拉角):**

根据旋转矩阵 $R_6^0$ 提取 Roll-Pitch-Yaw 角度:

```
roll  = atan2(R[2][1], R[2][2])
pitch = atan2(-R[2][0], sqrt(R[2][1]² + R[2][2]²))
yaw   = atan2(R[1][0], R[0][0])
```

### 4.3 逆运动学 (Pieper 解法)

系统采用解析法（Pieper解法），利用腕部三个关节轴线相交于一点的特点，将逆运动学分解为位置和姿态两个子问题。

**步骤1: 腕部中心位置求解**

腕部中心 $P_w$ 位于关节4、5、6轴线的交点:

$$P_w = P_{ee} - d_6 \cdot z_{ee}$$

其中 $P_{ee}$ 为末端位置, $z_{ee}$ 为末端Z轴方向, $d_6 = 65mm$。

**步骤2: 前三个关节角度求解**

$$\theta_0 = \text{atan2}(P_{w,y}, P_{w,x})$$

利用余弦定理求解 $\theta_1$ 和 $\theta_2$:

```
L1 = 120mm  (肩部到肘部)
L2 = 110mm  (肘部到腕部中心投影)
d1 = 85mm   (基座高度)

r = sqrt(P_w.x² + P_w.y²)
h = P_w.z - d1
D = (r² + h² - L1² - L2²) / (2 * L1 * L2)

θ₂ = atan2(±sqrt(1-D²), D)  # 正负号对应肘部上下配置

α = atan2(h, r)
β = atan2(L2*sin(θ₂), L1 + L2*cos(θ₂))
θ₁ = α - β - 90°
```

**步骤3: 后三个关节角度求解**

根据腕部姿态矩阵 $R_3^6$ 分解:

```
θ₃ = atan2(R[1][2], R[0][2])  # 腕部俯仰
θ₄ = atan2(sqrt(R[0][2]²+R[1][2]²), R[2][2])  # 腕部旋转
θ₅ = atan2(R[2][1], -R[2][0])  # 夹爪开合
```

**多解选择策略:**

| 优先级 | 准则 | 说明 |
|--------|------|------|
| 1 | 关节限位 | 排除超出限位的解 |
| 2 | 最小关节位移 | 选择与当前关节角度总变化最小的解 |
| 3 | 肘部朝上 | 优先选择肘部朝上的配置 |
| 4 | 避免奇异点 | 排除接近奇异位形的解 |

### 4.4 PWM-角度映射

舵机控制使用PWM值 (500-2500), 需要与关节角度建立映射关系:

```
θ_joint = (PWM - PWM_CENTER) / PWM_GAIN  (度)
其中:
  PWM_CENTER = 1500 (中位)
  PWM_GAIN ≈ 11.11 (约 90° 对应 ±1000 PWM范围)
```

### 5.3 AprilTag 6-DOF 位姿估计

**算法流程:**

```
1. 图像采集: sensor.snapshot() → QVGA (320×240)
2. 标签检测: find_apriltags() 使用 TAG36H11 族
3. 位姿估计: 已知标签尺寸 (50mm × 50mm) + 相机内参
4. 坐标系变换: 相机坐标系 → 世界坐标系
5. 输出: 标签ID, 3D位置(x,y,z), 3D姿态(rx,ry,rz)
```

**相机内参 (OpenMV H7 Plus, OV5640):**

```
fx = 315.0  (焦距, 像素)
fy = 315.0
cx = 160.0  (主点, 图像中心)
cy = 120.0
```

**标签尺寸:** 50mm × 50mm (TAG36H11)

**支持的标签ID:** 0-9 (10个标签)

**位姿估计精度:**
- 位置精度: ±3mm (距离 300mm 以内)
- 姿态精度: ±2° (距离 300mm 以内)
- 有效距离: 50mm - 500mm

### 5.3.1 像素 → 相机 → 机器人基座 坐标链路

视觉目标定位必须经过完整的手眼标定链路，而不能把像素坐标当作毫米直接外推：

```
像素 (u,v) ──K⁻¹──► 相机系 (x_cam, y_cam, z_cam) ──手眼(R,t)──► 机器人基座系 (x,y,z)
```

**步骤 1: 像素 → 相机系（归一化）**

给定像素 `(u,v)` 与相机深度 `z_cam`，利用相机内参矩阵 `K` 求逆：

```
x_cam = (u - cx) / fx * z_cam
y_cam = (v - cy) / fy * z_cam
z_cam = z
```

**步骤 2: 相机系 → 机器人基座系（手眼变换）**

```
[x]       [r11 r12 r13] [x_cam]   [tx]
[y]   =   [r21 r22 r23] [y_cam] + [ty]
[z]       [r31 r32 r33] [z_cam]   [tz]
```

**本项目标定参数（与 `config/settings.yaml` 及训练数据一致）：**

| 参数 | 值 | 单位 |
|------|-----|------|
| fx / fy | 320.0 | 像素 |
| cx / cy | 160.0 / 120.0 | 像素 |
| 手眼旋转 R | [[1,0,0],[0,-1,0],[0,0,-1]] | - |
| 手眼平移 t | [-100, -200, 50] | mm |

**工作空间对齐：** 训练数据生成与 RPi 运行时 `orchestrator.workspace_bounds` 统一为 `x∈[0,500]`, `y∈[0,500]`, `z∈[0,300]`（单位 mm），确保 IK/运动/安全/碰撞模型训练与部署一致。

**关键修复：** 早期版本将像素坐标按线性比例直接外推为 mm，导致约 735.5mm 的定位误差。现已统一改为上述 `K⁻¹ + 手眼变换` 链路，配合 `vision_agent.coordinate_transform_to_robot()` 使视觉→运动链路贯通。

### 5.4 质量检测算法

**检测流程:**

```
1. 图像采集: 高分辨率模式 (640×480)
2. ROI提取: 根据目标位置裁剪检测区域
3. 缺陷检测:
   a. 边缘检测: Canny 边缘检测算法
   b. 轮廓分析: 查找不规则轮廓 (缺陷)
   c. 面积计算: 统计缺陷面积
4. 颜色一致性检测:
   a. 颜色直方图: 计算ROI内颜色分布
   b. 方差计算: 评估颜色均匀性
5. 尺寸检测:
   a. 目标尺寸测量: 基于像素-毫米映射
   b. 与期望尺寸比较
6. 综合评分: 加权计算质量分数
```

**质量评分规则:**

| 项目 | 权重 | 满分 | 评分标准 |
|------|------|------|---------|
| 缺陷面积 | 40% | 40 | 缺陷面积 < 20px: 满分; > 200px: 0分 |
| 颜色一致性 | 30% | 30 | 方差 < 10: 满分; > 30: 0分 |
| 尺寸精度 | 30% | 30 | 偏差 < 1mm: 满分; > 5mm: 0分 |

**通过标准:** 总分 >= 70 分

## 7. 轨迹规划算法

### 7.1 轨迹类型

| 类型 | 说明 | 适用场景 |
|------|------|---------|
| S曲线 (S-Curve) | 加速度连续变化，冲击最小 | 精确点到点运动 |
| 梯形速度 (Trapezoidal) | 加速-匀速-减速三段 | 快速点到点运动 |
| 线性插值 (Linear) | 等时间间隔等角度增量 | 简单运动 |
| 关节空间 (Joint Space) | 各关节独立规划 | 关节空间运动 |
| 笛卡尔空间 (Cartesian) | 末端执行器直线/圆弧 | 精确路径跟踪 |

### 7.2 S曲线轨迹规划

**S曲线七段模型:**

```
阶段1: 加加速度段 (jerk = +J_max)
阶段2: 匀加速段  (acc = +A_max)
阶段3: 减加速度段 (jerk = -J_max)
阶段4: 匀速段    (vel = V_max)
阶段5: 加减速度段 (jerk = -J_max)
阶段6: 匀减速段  (acc = -A_max)
阶段7: 减减速度段 (jerk = +J_max)
```

**运动学参数:**

| 参数 | 符号 | 典型值 | 单位 |
|------|------|--------|------|
| 最大速度 | V_max | 500 | PWM/s |
| 最大加速度 | A_max | 200 | PWM/s² |
| 最大加加速度 | J_max | 100 | PWM/s³ |
| 采样周期 | Ts | 10 | ms |

**计算公式:**

```
位置: p(t) = p₀ + v₀·t + ½·a₀·t² + ⅙·j·t³
速度: v(t) = v₀ + a₀·t + ½·j·t²
加速度: a(t) = a₀ + j·t
```

### 7.3 笛卡尔空间直线轨迹

**算法步骤:**

```
1. 输入: 起点位姿 P_start, 终点位姿 P_end, 速度 v
2. 计算直线距离: L = ||P_end - P_start||
3. 计算总时间: T = L / v
4. 采样点数: N = T / Ts
5. 对于每个采样点 i ∈ [0, N]:
   a. 参数 t = i / N
   b. 插值位置: P(t) = P_start + t * (P_end - P_start)
   c. 插值姿态: 使用 SLERP (球面线性插值)
   d. 逆运动学求解: q(t) = IK(P(t))
   e. 存储关节角度 q(t)
6. 输出: 关节角度序列 [q₀, q₁, ..., qN]
```

### 7.4 速度规划

**速度曲线类型选择逻辑:**

```
if 距离 < 临界距离:
    使用梯形速度曲线 (加速→减速)
elif 精度要求高:
    使用S曲线 (7段)
else:
    使用梯形速度曲线 (加速→匀速→减速)
```

### 8.1 三层安全架构

```
┌─────────────────────────────────────────────────────────────┐

│                    第2层: 固件安全 (Firmware)                 │

├─────────────────────────────────────────────────────────────┤
│                    第1层: 硬件安全 (Hardware)                 │
│  紧急停止按钮 | 限位开关 | 电流检测 | 继电器断电              │
│  电源保护 | 过温保护 | 硬件看门狗                             │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 安全监控指标

| 监控项 | 阈值 | 动作 | 响应时间 |
|--------|------|------|---------|
| 关节位置超限 | > 限位值 | 立即停止该关节 | < 10ms |
| 关节速度超限 | > 500 PWM/s | 降低速度至安全值 | < 50ms |
| 工作空间超限 | 末端超出范围 | 停止运动 | < 100ms |
| 碰撞检测 | 力矩突变 > 阈值 | 紧急停止 | < 10ms |
| 通信超时 | > 500ms 无响应 | 紧急停止 | < 500ms |
| 电压异常 | < 6V 或 > 8.4V | 停止运动并报警 | < 100ms |
| 温度异常 | > 70°C (舵机) | 停止该舵机 | < 500ms |
| 看门狗超时 | > 1s 未喂狗 | 系统复位 | < 1s |

### 8.3 紧急停止时序

```
  T=0ms:    紧急停止信号触发 (按钮/软件/传感器)
  T=0-1ms:  STM32 中断响应 → 设置ESTOP标志
  T=1-2ms:  发送停止命令到所有舵机 (#255P0000T0000!)
  T=2-5ms:  继电器断开舵机电源 (可选硬件切断)
  T=5ms:    通过UART通知RPi状态变更
  T=10ms:   RPi发送WebSocket通知小程序
  T=50ms:   系统进入安全状态，等待人工复位
```

### 13.8 Round 11 重训说明（坐标对齐 + 碰撞修复）

针对前序会话发现的问题（工作空间不匹配、像素坐标线性外推误差、碰撞类别失衡），Round 11 进行了系统化修复与重训：

**1. 工作空间对齐**

| 维度 | 修复前 | 修复后 |
|------|--------|--------|
| x / y | -500 ~ +500 | 0 ~ 500 mm |
| z | -500 ~ +500 | 0 ~ 300 mm |

训练数据生成 (`training/data_generator.py`) 与 RPi 运行时 `orchestrator.workspace_bounds` 保持一致，使 IK/运动/安全/碰撞模型训练与部署分布一致。

**2. 坐标变换修复**

视觉数据集的目标坐标由「像素线性外推」改为「`K⁻¹` 归一化 → 手眼 `(R,t)` 变换」完整链路（见 §5.3.1），消除约 735.5mm 的定位误差。`pixel_to_robot()` / `robot_to_pixel()` 已与 `config/settings.yaml` 的手眼参数保持一致。

**3. 碰撞类别失衡修复**

真实碰撞数据集正样本率仅约 2.53%（45000 样本中 1140 个碰撞）。修复前阈值在「过采样后的验证集」上搜索，导致部署阈值偏高、真实分布召回率不足。

修复方案：
- 归一化在原始分布上进行；过采样仅作用于训练集（碰撞类提升至 30%）。
- 决策阈值在**原始（非过采样）验证集**上搜索（范围 0.02~0.9），贴近真实 ~2.5% 部署分布。
- 安全关键场景以「高召回」优先：测试标准为召回率 ≥ 0.85 且精确率 ≥ 0.20。

**3.5 Round 12 碰撞边界规则对齐（召回率修复）**

Round 11 独立验证虽在验证集上达标，但在**全量真实数据集**上召回率仅 0.30（独立测试 FAIL）。排查根因：真实生成器 `generate_multi_obstacle_collision` 以 `min_dist < 半径 + 30`（半径 U(10,60)，边界 40~90mm）判定碰撞，而训练时的合成数据以固定 `min_dist < 25mm` 标记碰撞。两种规则不一致，使模型学到过紧的 ~25mm 碰撞边界，将真实碰撞（40~90mm）判为安全 → 召回率崩塌。

Round 12 修复（`training/model_trainer.py`）：
- 合成碰撞规则改为与真实一致：每场景采样代表障碍半径 `U(10,60)`，以 `min_dist < 半径 + 30` 标记标签。
- 新增两个特征：`eff_radius`（最近障碍半径）与 `clearance = min_dist - (半径 + 30)`（负值即越界），让模型显式学习可变碰撞边界。
- 阈值搜索改为「召回率 ≥ 0.85 约束下最大化精确率」，直接匹配安全关键测试标准。

Round 12 独立验证（`training/test_models.py`）：
- 召回率 **0.30 → 1.00**，精确率 0.29，阈值 0.28，**FAIL → PASS**。

### 13.2 Motion IK 模型

**目的:** 使用神经网络预测逆运动学初始解，加速解析法收敛。

**架构:**
```
输入层 (6维: x, y, z, roll, pitch, yaw)
  → 隐藏层1 (128维, ReLU)
  → 隐藏层2 (256维, ReLU)
  → 隐藏层3 (256维, ReLU)
  → 输出层 (6维: 关节角度)
```

**训练数据:** 2000 个样本，覆盖工作空间均匀采样点
**训练轮次:** 500 epochs
**收敛时间:** 21.9s

### 13.3 Quality 模型 (v2 增强版)

**目的:** 基于缺陷特征预测产品质量评分（0-100分）。

**特征工程 (23维):**
- 缺陷计数 (4维): 总数、严重数、中等数、轻微数
- 面积指标 (3维): 总面积、最大面积、平均面积
- 严重度加权 (1维): 加权评分 (severe=9, moderate=4, minor=1)
- 缺陷类型编码 (8维): 划痕、变色、尺寸误差、表面缺陷、颜色不一致、缺失特征、污染、变形
- 空间聚类 (1维): 缺陷聚集度指标
- 缺陷密度 (1维): 单位面积缺陷数
- 产品类型编码 (3维): default, precision, coarse
- 特征交互 (2维): 严重度×面积、缺陷数×最大严重度

**性能提升:**
| 指标 | v1.0 | v2.0 | 提升 |
|------|------|------|------|
| R² | 0.363 | 0.803 | +121% |
| MAE | 12.4 | 6.87 | -44.6% |
| RMSE | 15.3 | 8.54 | -44.2% |

### 13.4 Safety 模型 (v2 增强版)

**目的:** 实时分类安全状态 (OK / WARNING / DANGER / ESTOP)。

**特征工程 (27维):**
- 关节位置 (6维): 当前关节角度
- 关节速度 (6维): 移动平均滤波速度
- 距离限位 (6维): 到最大/最小限位的距离
- 速度比率 (6维): 当前速度/最大速度
- 心跳状态 (1维): STM32 连接状态
- 最近事件 (1维): 是否有近期安全事件
- 工作空间边界 (1维): 是否接近边界

**最优阈值搜索:** 在验证集上搜索最优分类阈值使 F1 最大化。

**性能提升:**

|------|------|------|------|
| Accuracy | 79.0% | 97.3% | +23.2% |
| Precision | 0.76 | 0.97 | +27.6% |
| Recall | 0.82 | 0.99 | +20.7% |
| F1 Score | 0.79 | 0.98 | +24.1% |

### 13.5 Collision 模型

**目的:** 快速检测路径点与障碍物的碰撞风险（安全关键，高召回优先）。

**架构:** 5-模型集成 SimpleNN（全连接：19 → 128 → 64 → 64 → 32 → 16 → 1，tanh + batch-norm + sigmoid 输出）
**特征（19 维）:** 障碍距离（min/mean/std/range）、障碍计数（n_obstacles/n_close/n_very_close）、速度（max/mean）、接近角、碰撞时间 TTC、综合风险、**最近障碍半径 `eff_radius`**、**净空 `clearance`**、关节中心距、速度-距离比、角分布、近邻占比、风险-速度积
**独立验证:** 召回率 1.00，精确率 0.29（阈值 0.28，45000 全量真实样本）

## 14. 工业级升级方向

当前系统为实验室原型，在精度、实时性、通信带宽与安全等级上尚未对标工业级。规划从 **硬件、通信、控制算法、视觉感知、软件架构、安全认证** 六个维度分三阶段重构，最终达到绝对精度 ±0.1mm、MTBF > 5000h、安全等级 ISO 13849 PLr d、防护 IP54+：

| 维度 | 方向 |
|------|------|
| 硬件 | 绝对编码器闭环（AS5048）、谐波减速、STM32H7/安全协处理器 |
| 通信 | CAN 1Mbps / EtherCAT、CRC32 + 重发、确定性调度 |
| 控制 | 动力学前馈（重力/摩擦）、MPC 1ms 周期、动量观测器、柔顺力控 |
| 视觉 | 工业全局快门相机 + Jetson Orin + YOLO 6D 位姿、在线畸变校正 |
| 架构 | ROS2 分布式、行为树替代 FSM、InfluxDB + AIOps |
| 安全 | ISO 13849 PLr d、双通道急停、安全继电器、CE 认证 |
