## 1. 威胁模型

### 1.1 攻击面识别

系统共识别出以下攻击面，按风险等级排列：

| 攻击面 | 接口类型 | 物理访问要求 | 风险等级 | 潜在影响 |
|--------|---------|------------|---------|---------|
| UART通信 (RPi↔STM32) | 串口 (3.3V TTL) | 需要 | 中 | 命令注入、数据篡改 |
| UART通信 (STM32↔OpenMV) | 串口 (3.3V TTL) | 需要 | 低 | 视觉数据篡改 |
| WiFi 网络 | 802.11 b/g/n | 不需要 | 高 | 未经授权访问、数据窃听 |
| REST API | HTTPS (TCP 8000) | 不需要 | 高 | 注入攻击、权限绕过 |
| WebSocket | WSS (TCP 8001) | 不需要 | 中 | 消息伪造、DoS |
| SWD 调试接口 | SWD (PA13/PA14) | 需要 | 中 | 固件提取、篡改 |
| USB 接口 | USB (STM32/OpenMV) | 需要 | 中 | 固件篡改、恶意代码 |
| 物理访问 | 直接接触设备 | 需要 | 高 | 硬件篡改、传感器欺骗 |
| 电源接口 | 供电线路 | 需要 | 低 | 断电、过压攻击 |

### 1.2 威胁场景矩阵

| 威胁场景 | 攻击者画像 | 攻击向量 | 影响 | 缓解措施 |
|---------|-----------|---------|------|---------|
| 远程未经授权控制 | 外部攻击者 | WiFi嗅探 + API攻击 | 机械臂被恶意控制 | JWT认证 + HTTPS + 访问控制 |
| 中间人攻击 (MITM) | 网络内攻击者 | ARP欺骗 + 流量劫持 | 通信数据泄露/篡改 | TLS 1.3 + 证书固定 |
| 固件篡改 | 物理访问者 | SWD重编程 | 安全功能旁路 | Flash读保护 + 安全启动 |
| 拒绝服务攻击 | 远程攻击者 | API洪水攻击 | 系统不可用 | 速率限制 + 连接限制 |
| 视觉传感器欺骗 | 物理接近者 | 伪造标记/颜色 | 错误采样目标 | 多传感器交叉验证 |
| 电源攻击 | 物理访问者 | 过压/断电 | 硬件损坏 | 电源保护电路 |
| 侧信道攻击 | 物理接近者 | 功耗分析 | 密钥泄露 | 物理防护 + 恒定时间算法 |
| 供应链攻击 | 第三方 | 依赖库投毒 | 后门代码 | 依赖审计 + 代码签名 |

### 1.3 风险评估矩阵

```
                    影响程度
              低        中        高        严重
          ┌─────────┬─────────┬─────────┬─────────┐
    很高  │  UART   │  SWD    │  API    │  WiFi   │
发生       │  窃听   │  攻击   │  DDoS   │ RCE漏洞 │
概率       ├─────────┼─────────┼─────────┼─────────┤
    高    │  电源   │  DoS    │  MITM   │ 未授权  │
          │  波动   │  攻击   │  攻击   │  控制   │
          ├─────────┼─────────┼─────────┼─────────┤
    中    │  传感器 │  USB    │  数据   │  固件   │
          │  欺骗   │  攻击   │  泄露   │  篡改   │
          ├─────────┼─────────┼─────────┼─────────┤
    低    │  物理   │  侧信道 │  供应链 │         │
```

## 2. 通信安全

### 2.1 UART 协议安全加固

**当前风险:**
- UART通信为明文传输，可被物理接入者窃听
- 无消息认证机制，可被注入恶意命令
- 无重放攻击防护

**加固措施:**

| 措施 | 说明 | 实现层 |
|------|------|--------|
| 帧校验 | 为每个帧添加 CRC-8 校验 | STM32 固件 |
| 命令白名单 | 只接受预定义命令集 | STM32 协议解析器 |
| 参数范围检查 | 拒绝超出物理范围的参数 | STM32 app_arm.c |
| 速率限制 | 限制命令频率 (≤ 100 条/秒) | STM32 + RPi |
| 响应超时 | 500ms 无响应触发安全状态 | RPi stm32_comm.py |
| 物理防护 | 串口引脚不外露，使用内部连接 | 硬件设计 |

**增强帧格式 (带校验):**

```
#<CMD>:<PARAM1>,<PARAM2>,...!<CRC8>\r\n

其中 CRC8 = CRC-8-CCITT (frame bytes between # and !)
```

**命令白名单实现 (C语言伪代码):**

```c
static const char* ALLOWED_COMMANDS[] = {
    "ARM", "JNT", "ACT", "STATUS", "ESTOP",
    "HOME", "SPEED", "ACC", "VIS", "SENS",
    "CONF", "PING", "INFO", NULL
};

int is_command_allowed(const char* cmd) {
    for (int i = 0; ALLOWED_COMMANDS[i] != NULL; i++) {
        if (strcmp(cmd, ALLOWED_COMMANDS[i]) == 0) return 1;
    }
    return 0;
}
```

### 2.2 API 认证与授权

**认证方案: JWT (JSON Web Token)**

| 参数 | 值 |
|------|------|
| 算法 | HS256 (HMAC-SHA256) |
| 密钥长度 | 256 bit |
| 密钥存储 | 树莓派环境变量或 secrets 文件 |
| Token 有效期 | 24 小时 |
| Refresh Token | 支持，7天有效期 |

**JWT Payload 结构:**

```json
{
  "sub": "user_id",
  "role": "operator",
  "iat": 1690000000,
  "exp": 1690086400,
  "jti": "unique-token-id"
}
```

**角色权限模型:**

| 角色 | 权限 |
|------|------|
| `admin` | 全部权限：系统配置、固件更新、用户管理 |
| `operator` | 操作权限：任务管理、机械臂控制、监控查看 |
| `viewer` | 只读权限：状态查看、监控查看、历史记录 |

**API 认证流程:**

```
1. 客户端 POST /api/v1/auth/login {username, password}
2. 服务端验证凭据，返回 {access_token, refresh_token}
3. 客户端在后续请求中携带: Authorization: Bearer <access_token>
4. Token 过期后使用 refresh_token 获取新 token
```

### 2.3 WebSocket 安全

| 安全措施 | 说明 |
|---------|------|
| TLS 加密 | WSS 协议 (WebSocket over TLS) |
| Token 认证 | 连接时携带 JWT token |
| 消息验证 | 服务端验证消息格式和来源 |
| 连接限制 | 每 IP 最多 5 个并发连接 |
| 心跳检测 | 30 秒心跳超时自动断开 |
| 消息大小限制 | 单条消息 ≤ 64KB |
| 频率限制 | 客户端每秒最多 50 条消息 |

## 3. 硬件安全

### 3.1 紧急停止电路

**电路设计:**

```
  +7.4V 舵机电源
       │
       ├──[保险丝 5A]──┐
       │                │
       │           ┌────▼────┐
       │           │ 继电器   │  (常开)
       │           │ SRD-05VDC│
       │           └────┬────┘
       │                │ (NC端)
       │                │
  [紧急停止按钮]        │
  (常闭, 红色蘑菇头)     │
       │                │
       └────────────────┤
                        │
                   ┌────▼────┐
                   │ 舵机电源 │
                   │ VCC 输入 │
                   └─────────┘

  控制逻辑:
  - 正常状态: 继电器闭合，舵机供电
  - 紧急停止: 按钮按下 → 继电器断开 → 舵机断电
  - STM32 PB12 控制继电器 (软件也可触发断电)
```

| 参数 | 值 |
|------|------|
| 继电器型号 | SRD-05VDC |

| 按钮直径 | 40mm |
| 响应时间 | < 5ms (机械) |
| 失效模式 | 故障安全 (断电=停止) |

| 参数 | 值 |

| 预分频器 | 64 (625 Hz) |
| 重载值 | 625 (1秒) |
| 喂狗周期 | 100ms (主循环) |
| 超时动作 | 系统复位 |

**窗口看门狗 (WWDG):**

| 参数 | 值 |
|------|------|

| 预分频器 | 8 |
| 窗口值 | 0x50 (80) |

```c
// 独立看门狗初始化
void IWDG_Init(void) {

// 主循环中喂狗
void IWDG_Feed(void) {
    IWDG_ReloadCounter();
}
```

## 4. 软件安全

### 4.1 关节限位保护

**软件限位值 (PWM):**

| 关节 | 最小值 | 最大值 | 归零值 |
|------|--------|--------|--------|
| Joint 0 (底座) | 500 | 2500 | 1500 |
| Joint 1 (肩部) | 600 | 2400 | 1500 |
| Joint 2 (肘部) | 600 | 2400 | 1500 |
| Joint 3 (腕部俯仰) | 500 | 2500 | 1500 |
| Joint 4 (腕部旋转) | 500 | 2500 | 1500 |
| Joint 5 (夹爪) | 500 | 1800 | 1000 |

**限位检查实现 (C):**

```c
typedef struct {
    uint16_t min_pwm;
    uint16_t max_pwm;
    uint16_t home_pwm;
    uint16_t current_pwm;
} JointLimits;

const JointLimits JOINT_LIMITS[6] = {
    {500, 2500, 1500, 0},  // Joint 0
    {600, 2400, 1500, 0},  // Joint 1
    {600, 2400, 1500, 0},  // Joint 2
    {500, 2500, 1500, 0},  // Joint 3
    {500, 2500, 1500, 0},  // Joint 4
    {500, 1800, 1000, 0},  // Joint 5
};

int check_joint_limits(uint8_t joint_id, uint16_t target_pwm) {
    if (target_pwm < JOINT_LIMITS[joint_id].min_pwm) return 0;
    if (target_pwm > JOINT_LIMITS[joint_id].max_pwm) return 0;
    return 1;
}
```

### 4.2 速度限制

| 参数 | 默认值 | 最大值 | 说明 |
|------|--------|--------|------|
| 全局速度系数 | 50% | 100% | 所有运动速度倍增系数 |
| 最大关节速度 | 500 PWM/s | 1000 PWM/s | 单个关节最大速度 |
| 末端最大线速度 | 200 mm/s | 500 mm/s | 末端执行器直线速度 |
| 加速度系数 | 30% | 60% | 加速度倍增系数 |

**速度渐变实现:**

```python
def limit_speed(current_pwm, target_pwm, max_step):
    """限制单步速度变化量"""
    delta = target_pwm - current_pwm
    if abs(delta) > max_step:
        delta = max_step if delta > 0 else -max_step
    return current_pwm + delta
```

### 4.3 碰撞检测

**检测方法:**

| 方法 | 原理 | 检测时间 | 准确度 |
|------|------|---------|--------|
| 电流突变检测 | 舵机电流超过正常值 | 10ms | 高 |
| 速度偏差检测 | 实际速度与预期速度偏差 | 50ms | 中 |
| 末端力估计 | 基于关节力矩推算末端力 | 20ms | 中 |
| 工作空间预测 | 运动学模型预判碰撞 | 实时 | 高 |

**碰撞检测阈值:**

| 参数 | 阈值 | 动作 |
|------|------|------|
| 电流突变 | > 2倍正常值 | 立即停止 |
| 速度偏差 | > 50% 预期值 | 降速50% |
| 末端力 | > 5N | 停止并反向退让 |
| 工作空间 | 末端超出预设范围 | 拒绝运动 |

### 4.4 工作空间边界

**工作空间定义 (以底座中心为原点, 单位 mm):**

| 轴 | 最小值 | 最大值 |
|------|--------|--------|
| X | -200 | +200 |
| Y | -200 | +200 |
| Z | 0 | +300 |

**边界检查:**

```python
def check_workspace_bounds(x, y, z):
    """检查目标点是否在工作空间内"""
    limits = {
        'x': (-200, 200),
        'y': (-200, 200),
        'z': (0, 300),
    }
    if not (limits['x'][0] <= x <= limits['x'][1]): return False
    if not (limits['y'][0] <= y <= limits['y'][1]): return False
    if not (limits['z'][0] <= z <= limits['z'][1]): return False
    return True
```

## 5. 固件安全

### 5.1 Flash 保护

| 保护措施 | 配置 | 说明 |
|---------|------|------|
| 读保护 (RDP) | Level 1 | 禁止通过SWD/JTAG读取Flash内容 |
| 写保护 (WRP) | 前4页 (4KB) | 保护启动代码和配置 |
| 选项字节保护 | 编程后锁定 | 防止恶意修改保护设置 |

**RDP 配置:**

```c
// 启用读保护 Level 1
FLASH_Unlock();
FLASH_OB_Unlock();
FLASH_OB_RDPConfig(OB_RDP_Level_1);
FLASH_OB_Launch();
FLASH_OB_Lock();
FLASH_Lock();
```

**Flash 区域划分:**

| 区域 | 地址范围 | 大小 | 保护 |
|------|---------|------|------|
| 启动代码 | 0x08000000 - 0x080003FF | 1KB | WRP |
| 配置参数 | 0x08000400 - 0x080007FF | 1KB | WRP |
| 固件代码 | 0x08000800 - 0x0800F7FF | 60KB | RDP |
| 运行时数据 | 0x0800F800 - 0x0800FFFF | 2KB | 无 |

### 5.2 安全启动考虑

由于 STM32F103C8T6 不支持硬件安全启动，系统采用以下软件级措施：

| 措施 | 说明 |
|------|------|
| 固件校验 | 启动时计算固件 CRC32 并与存储值比对 |
| 版本检查 | 比较版本号，拒绝降级 |
| 启动计数 | 记录启动次数，异常增长报警 |
| 配置完整性 | 校验配置区域 CRC，损坏时恢复默认值 |

**固件完整性检查 (启动时):**

```c
#define FIRMWARE_START  0x08000800
#define FIRMWARE_SIZE   0xF000  // 60KB
#define CRC_STORED_ADDR 0x080007F8

void check_firmware_integrity(void) {
    uint32_t calculated_crc = CRC_Calculate((uint32_t*)FIRMWARE_START, FIRMWARE_SIZE);
    uint32_t stored_crc = *(uint32_t*)CRC_STORED_ADDR;
    
    if (calculated_crc != stored_crc) {
        // 固件损坏，进入安全模式
        enter_safe_mode();
    }
}
```

### 5.3 固件更新安全

| 要求 | 说明 |
|------|------|
| 签名验证 | 固件更新包必须带有RSA数字签名 |
| 版本检查 | 只接受高于当前版本的更新 |
| 回滚保护 | 禁止安装低于当前版本的固件 |
| 完整性校验 | 传输完成后校验SHA-256 |
| 安全回退 | 更新失败自动回退到上一版本 |
| 更新日志 | 记录每次更新的时间、版本、操作者 |

## 6. 网络安全

### 6.1 HTTPS/TLS 配置

| 参数 | 值 |
|------|------|
| TLS 版本 | TLS 1.3 (优先), TLS 1.2 (兼容) |
| 证书类型 | 自签名证书 (开发) / Let's Encrypt (生产) |
| 密钥长度 | RSA 2048 bit |
| 加密套件 | ECDHE-RSA-AES256-GCM-SHA384 |
| HSTS | 启用 (max-age=31536000) |
| 证书路径 | `/etc/ssl/certs/rpi.crt`, `/etc/ssl/private/rpi.key` |

**FastAPI TLS 配置:**

```python
import uvicorn
import ssl

ssl_context = ssl.create_default_context(ssl.Purpose.CLIENT_AUTH)
ssl_context.load_cert_chain(
    certfile="/etc/ssl/certs/rpi.crt",
    keyfile="/etc/ssl/private/rpi.key"
)

uvicorn.run(
    app,
    host="0.0.0.0",
    port=8000,
    ssl_certfile="/etc/ssl/certs/rpi.crt",
    ssl_keyfile="/etc/ssl/private/rpi.key"
)
```

### 6.2 CORS 配置

| 参数 | 值 |
|------|------|
| 允许来源 | 生产环境限制为小程序域名 |
| 允许方法 | GET, POST, PUT, DELETE |

### 7.2 数据存储安全

**密码存储:**

```python
import bcrypt

def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12)).decode()

def verify_password(password: str, hashed: str) -> bool:
    return bcrypt.checkpw(password.encode(), hashed.encode())
```

**敏感配置加密:**

```python
from cryptography.fernet import Fernet

class ConfigEncryption:
    def __init__(self, key: bytes):
        self.cipher = Fernet(key)
    
    def encrypt(self, plaintext: str) -> bytes:
        return self.cipher.encrypt(plaintext.encode())
    
    def decrypt(self, ciphertext: bytes) -> str:
        return self.cipher.decrypt(ciphertext).decode()
```

### 8.3 紧急程序

**紧急停止操作流程:**

```
1. 发现异常情况
2. 立即按下紧急停止按钮 (红色蘑菇头)
3. 系统自动执行:
   a. 所有舵机断电
   b. 蜂鸣器持续报警
   c. 状态LED变为红色
   d. 小程序推送紧急通知
4. 操作员确认现场安全
5. 排除故障原因
6. 旋转紧急停止按钮复位
7. 通过小程序或控制台清除紧急状态
8. 系统执行自检
9. 自检通过后恢复正常运行
```

**火灾应急:**
1. 按下紧急停止按钮
2. 切断主电源
3. 使用 CO2 灭火器 (禁止使用水)
4. 通知相关人员

**人员受伤:**
1. 按下紧急停止按钮
2. 实施急救
3. 拨打急救电话
4. 保护现场，记录事故

## 9. 故障模式与恢复

### 9.1 故障模式分析 (FMEA)

| 故障模式 | 严重度 | 发生概率 | 检测方式 | 缓解措施 |
|---------|--------|---------|---------|---------|
| 舵机卡死 | 高 | 低 | 电流异常检测 | 紧急停止，更换舵机 |
| 舵机通信丢失 | 高 | 中 | 轮询超时 | 停止该舵机，报警 |
| STM32 死机 | 严重 | 低 | 看门狗复位 | 自动复位，恢复运行 |
| RPi 死机 | 高 | 低 | 心跳检测 | 自动重启，恢复任务 |
| OpenMV 通信丢失 | 中 | 中 | 超时检测 | 跳过视觉步骤，报警 |
| 电源故障 | 严重 | 低 | 电压检测 | 安全停止，备用电源 |
| 网络中断 | 低 | 中 | 心跳检测 | 离线运行，恢复后同步 |
| 传感器故障 | 中 | 低 | 值域检查 | 使用默认值，报警 |
| 夹爪掉落物体 | 中 | 中 | 电流检测 | 重新抓取，降低高度 |
| 机械臂碰撞 | 严重 | 低 | 力矩突变 | 紧急停止，反向退让 |

### 9.2 恢复程序

**自动恢复:**

| 故障 | 恢复策略 |
|------|---------|
| STM32看门狗复位 | 重新初始化所有外设，恢复上次状态 |
| RPi进程崩溃 | systemd 自动重启服务 |
| 网络中断 | 自动重连 (指数退避) |
| UART短暂错误 | 重试3次，间隔50ms |

**手动恢复:**

| 故障 | 恢复步骤 |
|------|---------|
| 紧急停止后 | 1. 排除故障 2. 复位按钮 3. 清除ESTOP状态 4. 归零 5. 恢复 |
| 舵机故障 | 1. 断电 2. 更换舵机 3. 校准 4. 测试 5. 恢复 |
| 电源故障 | 1. 检查电源 2. 更换保险丝 3. 重启系统 4. 自检 5. 恢复 |
