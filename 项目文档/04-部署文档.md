## 1. 快速开始 (5分钟部署)

如果你的树莓派已安装 Docker 和 Docker Compose，执行以下命令即可完成部署：

```bash
# 1. 克隆项目
cd ~
git clone <repository-url> zidongaixiangmu
cd ~/zidongaixiangmu/rpi_control

# 2. 配置环境变量
cp .env.example .env

# 3. 创建数据目录
mkdir -p data logs images reports

# 4. 配置串口权限
sudo usermod -a -G dialout $USER
# 重新登录使权限生效

# 5. 构建并启动
docker compose build
docker compose up -d

# 6. 验证
curl http://localhost:8000/api/health
```

## 2. 系统准备

### 2.1 烧录 Raspberry Pi OS

**步骤 1: 下载工具**

从 [Raspberry Pi 官网](https://www.raspberrypi.com/software/) 下载 Raspberry Pi Imager。

**步骤 2: 烧录系统**

```
1. 插入 MicroSD 卡到电脑 (建议 32GB+, Class 10)
2. 打开 Raspberry Pi Imager
3. 选择:
   - Raspberry Pi 设备: Raspberry Pi 4 (或你的型号)
   - 操作系统: Raspberry Pi OS (64-bit) Lite (推荐，无桌面环境)
   - 存储: 选择你的 MicroSD 卡
4. 点击右下角齿轮图标 "设置":
   ✓ 设置主机名: sampling-arm-pi
   ✓ 启用 SSH: 使用密码登录
   ✓ 设置用户名: pi (密码自定，如: sampling2024)
   ✓ 配置 WiFi: 填写你的 SSID 和密码
   ✓ 语言设置: Asia/Shanghai, UTF-8
5. 点击 "烧录" 并等待完成
```

### 2.2 首次启动与连接

```bash
# 将 MicroSD 卡插入树莓派，接通电源，等待 1-2 分钟

# 方法 A: 通过主机名连接 (推荐)
ssh pi@sampling-arm-pi.local

# 方法 B: 通过 IP 地址连接
# 在路由器管理页面查找树莓派 IP，或使用:
ping sampling-arm-pi.local
ssh pi@<树莓派IP地址>

# 方法 C: 通过显示器+键盘直接操作
```

### 2.3 系统基础配置

```bash
# 进入系统配置工具
sudo raspi-config

# 逐项配置:
# 1. System Options → Wireless LAN → 输入 WiFi 信息
# 2. Interface Options → SSH → Enable
# 3. Interface Options → Serial Port:
#    → "Would you like a login shell..." → 选择 NO
#    → "Would you like the serial port hardware..." → 选择 YES
# 4. Localisation Options → Timezone → Asia → Shanghai
# 5. Advanced Options → Expand Filesystem
# 6. Finish → 选择 Yes 重启
```

### 2.4 系统更新与基础工具安装

```bash
# 更新系统
sudo apt update && sudo apt upgrade -y
sudo apt autoremove -y

# 安装基础工具
sudo apt install -y \
    git curl wget vim \
    htop iotop \
    avahi-daemon \
    ufw

# 启动 mDNS 服务 (可通过主机名访问)
sudo systemctl enable avahi-daemon
sudo systemctl start avahi-daemon
```

### 2.5 配置静态 IP (推荐)

```bash
# 编辑 DHCP 配置
sudo nano /etc/dhcpcd.conf

# 在文件末尾添加 (根据你的网络环境调整):
interface wlan0
static ip_address=192.168.1.100/24
static routers=192.168.1.1
static domain_name_servers=192.168.1.1 8.8.8.8

# 重启网络服务
sudo systemctl restart dhcpcd
```

### 2.6 防火墙配置

```bash
# 允许必要端口
sudo ufw allow 22/tcp      # SSH
sudo ufw allow 8000/tcp    # REST API
sudo ufw allow 8001/tcp    # WebSocket

# 启用防火墙
sudo ufw --force enable

# 查看状态
sudo ufw status verbose
```

## 3. Docker 安装与配置

### 3.1 安装 Docker Engine

```bash
# 方法 A: 使用官方安装脚本 (推荐)
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
rm get-docker.sh

# 方法 B: 手动安装 (如果脚本方式不可用)
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

### 3.2 将当前用户添加到 docker 组

```bash
# 添加用户到 docker 组 (避免每次使用 sudo)
sudo usermod -aG docker $USER

# 使权限生效 (需要重新登录)
newgrp docker

# 验证
docker run hello-world
```

### 3.3 配置 Docker 自动启动

```bash
# 启用 Docker 开机自启
sudo systemctl enable docker
sudo systemctl enable containerd

# 验证状态
sudo systemctl status docker
```

### 3.4 配置 Docker 日志轮转 (防止日志占满磁盘)

```bash
# 创建 Docker 日志配置
sudo nano /etc/docker/daemon.json
```

添加以下内容:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "storage-driver": "overlay2"
}
```

```bash
# 重启 Docker 使配置生效
sudo systemctl restart docker
```

## 5. 容器构建与启动

### 5.1 构建 Docker 镜像

```bash
cd ~/zidongaixiangmu/rpi_control

# 构建镜像 (首次构建需要 5-10 分钟)
docker compose build

# 如果构建失败，使用 --no-cache 强制重新构建
docker compose build --no-cache
```

**构建说明:**

Dockerfile 采用多阶段构建:
- **构建阶段 (builder)**: 安装 gcc/g++ 编译工具链和 Python 依赖
- **生产阶段**: 仅安装运行时依赖，镜像体积更小

### 5.2 启动服务

```bash
# 启动主控服务 (后台运行)
docker compose up -d

# 查看启动日志
docker compose logs -f

# 按 Ctrl+C 退出日志查看
```

### 5.3 服务管理命令

```bash
# 查看服务状态
docker compose ps

# 查看实时日志
docker compose logs -f rpi-control

# 查看最近 100 行日志
docker compose logs --tail=100 rpi-control

# 重启服务
docker compose restart

# 停止服务
docker compose stop

# 停止并删除容器
docker compose down

# 停止并删除容器+数据卷
docker compose down -v

# 更新镜像并重启
docker compose down
docker compose build --no-cache
docker compose up -d
```

### 5.4 可选服务启动


## 8. 开机自启配置

### 8.1 Docker Compose 自启 (推荐)

Docker Compose 文件已配置 `restart: unless-stopped`，容器会在以下情况自动重启:
- Docker 守护进程重启
- 系统重启
- 容器异常退出

验证自动重启:

```bash
# 重启树莓派
sudo reboot

# 重新连接后检查容器状态
ssh pi@sampling-arm-pi.local
docker compose -f ~/zidongaixiangmu/rpi_control/docker-compose.yml ps
```

### 8.2 使用 systemd 管理 Docker Compose (备选)

如果需要在 Docker 启动前执行某些操作，可以使用 systemd:

```bash
# 创建 systemd 服务文件
sudo nano /etc/systemd/system/sampling-arm-docker.service
```

```ini
[Unit]
Description=Sampling Arm Docker Compose Service
Requires=docker.service
After=docker.service network.target

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/home/pi/zidongaixiangmu/rpi_control
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
ExecReload=/usr/bin/docker compose restart
User=pi
Group=docker

[Install]
WantedBy=multi-user.target
```

```bash
# 启用服务
sudo systemctl daemon-reload
sudo systemctl enable sampling-arm-docker.service
sudo systemctl start sampling-arm-docker.service

# 查看状态
sudo systemctl status sampling-arm-docker.service
```

## 9. 硬件串口配置

### 9.1 树莓派串口映射

```
Raspberry Pi 串口架构:
  /dev/serial0  → /dev/ttyAMA0  (硬件串口, GPIO14 TXD, GPIO15 RXD)
  /dev/serial1  → /dev/ttyS0    (mini UART, 不稳定, 不推荐)
```

### 9.2 禁用蓝牙释放硬件串口

```bash
# 编辑 boot 配置
sudo nano /boot/firmware/config.txt
# 或 (旧版系统):
sudo nano /boot/config.txt

# 添加以下行:
dtoverlay=disable-bt
enable_uart=1

# 禁用蓝牙服务
sudo systemctl disable hciuart
sudo systemctl disable bluetooth
```

### 9.3 禁用串口控制台

```bash
# 禁用 getty 服务
sudo systemctl stop serial-getty@ttyAMA0.service
sudo systemctl disable serial-getty@ttyAMA0.service
sudo systemctl stop serial-getty@serial0.service
sudo systemctl disable serial-getty@serial0.service

# 从 cmdline.txt 中移除 console=serial0,115200
sudo nano /boot/firmware/cmdline.txt
# 删除: console=serial0,115200 (如果有)
```

### 9.4 设置串口权限

```bash
# 创建 udev 规则
sudo nano /etc/udev/rules.d/99-serial.rules
```

添加:

```
KERNEL=="ttyAMA0", MODE="0666"
KERNEL=="ttyUSB0", MODE="0666"
KERNEL=="ttyS0", MODE="0666"
```

```bash
# 重新加载规则
sudo udevadm control --reload-rules
sudo udevadm trigger

# 将用户添加到 dialout 组
sudo usermod -a -G dialout $USER
```

### 9.5 重启并验证

```bash
sudo reboot
```

```bash
# 重新连接后验证
ssh pi@sampling-arm-pi.local

# 检查串口设备
ls -la /dev/serial*
# 预期输出:
# lrwxrwxrwx /dev/serial0 -> ttyAMA0
# lrwxrwxrwx /dev/serial1 -> ttyS0

# 检查权限
ls -la /dev/ttyAMA0
# 应显示: crw-rw-rw- (或至少 crw-rw----)

# 测试串口 (需要先连接 STM32)
sudo minicom -D /dev/serial0 -b 115200
# 发送: #PING:!\r\n
# 预期响应: #PING:PONG,<timestamp>!\r\n
```

## 11. 系统校准

### 11.1 舵机零位校准

```bash
cd ~/zidongaixiangmu/rpi_control
source venv/bin/activate

# 运行校准脚本
python scripts/calibrate_arm.py
```

**校准流程:**

```
1. 脚本依次将每个舵机移动到中位 (PWM=1500)
2. 检查机械臂物理姿态:
   - Joint 0: 底座朝正前方
   - Joint 1: 大臂垂直
   - Joint 2: 小臂垂直
   - Joint 3: 腕部水平
   - Joint 4: 夹爪朝正前方
   - Joint 5: 夹爪闭合
3. 如有偏差，输入偏移值 (PWM 微调)
4. 参数保存到 config/arm_params.yaml
```

### 11.2 相机标定

```bash
cd ~/zidongaixiangmu/rpi_control
source venv/bin/activate

# 运行相机标定
python scripts/camera_calibrate.py
```

**标定步骤:**

```
1. 准备棋盘格标定板 (7×10 方格, 方格边长 20mm)
2. 将标定板放在 OpenMV 摄像头前方
3. 运行标定脚本
4. 从不同角度拍摄 15-20 张图像
5. 脚本自动计算相机内参矩阵和畸变系数
6. 结果保存到 config/ 目录
```

### 11.3 手眼标定

```bash
cd ~/zidongaixiangmu/rpi_control
source venv/bin/activate

# 运行手眼标定
python scripts/hand_eye_calibrate.py
```

**标定步骤:**

```
1. 在机械臂末端固定 AprilTag 标记 (50mm)
2. 运行标定脚本
3. 机械臂自动移动到 10-15 个不同姿态
4. 每个姿态下 OpenMV 检测 AprilTag 位姿
5. 脚本求解手眼变换矩阵 (相机→机械臂末端)
6. 结果保存到 config/arm_params.yaml
```

## 14. 常见问题排查

### 14.1 Docker 问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 构建失败 | 网络问题 | 配置 Docker 镜像加速器 |
| 容器启动后立即退出 | 配置错误 | `docker compose logs rpi-control` 查看日志 |
| 端口冲突 | 8000/8001 已被占用 | 修改 .env 中的 API_PORT/WS_PORT |
| 容器无法访问硬件 | 设备未映射 | 检查 docker-compose.yml 中 devices 配置 |
| 磁盘空间不足 | 日志/数据积累 | `docker system prune -a` 清理 |

### 14.2 串口问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 无法打开串口 | 权限不足 | `sudo usermod -a -G dialout $USER` |
| 串口数据乱码 | 波特率不匹配 | 确认所有设备波特率一致 (115200) |
| 串口无响应 | 接线错误 | 检查 TX/RX/GND 连接 |
| /dev/serial0 不存在 | 未启用 UART | 运行 raspi-config 启用 Serial Port |

### 14.3 模型训练问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 训练内存不足 | 数据集太大 | 减少数据集大小或增加 swap |
| 训练速度慢 | RPi 性能限制 | 在 PC 上训练后复制模型文件 |
| 模型加载失败 | pickle 版本不兼容 | 使用相同 Python 版本训练和加载 |
| F1 分数低 | 数据分布不均 | 检查数据集平衡性 |

### 14.4 性能问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| API 响应慢 | CPU 负载高 | 检查 `htop`，关闭不必要的服务 |
| 内存不足 | 容器内存限制 | 调整 docker-compose.yml 中的 memory limits |
| SD 卡写入慢 | SD 卡性能差 | 使用 Class 10 或更高速度的 SD 卡 |
| 系统过热 | 散热不足 | 添加散热片或风扇 |
