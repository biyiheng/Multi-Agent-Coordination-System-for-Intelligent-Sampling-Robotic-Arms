## 2. 镜像版本与标签策略

建议采用「语义化版本 + 环境标签」双标签：

```
sampling-arm:<版本>         # 例: sampling-arm:2.1.0
sampling-arm:<版本>-<hash>  # 例: sampling-arm:2.1.0-abc1234（不可变，用于精准回滚）
sampling-arm:latest          # 跟随最新稳定版
```

**规范**
- 每次发布使用不可变标签（版本+commit hash）以便回滚。
- `latest` 仅在验证通过后更新。
- 禁止覆盖已发布的不可变标签。

## 3. 构建多架构镜像

在开发机（x86_64）上为树莓派（arm64）交叉构建：

```bash
cd ~/zidongaixiangmu/rpi_control

# 确保 buildx 可用
docker buildx version

# 创建并使用多架构构建器（若不存在）
docker buildx create --name multiarch --use 2>/dev/null || docker buildx use multiarch

# 登录仓库（见第 4 节）

# 构建并推送多架构镜像（一次完成两平台）
export IMAGE=yourname/sampling-arm:2.1.0
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t $IMAGE \
  -t yourname/sampling-arm:latest \
  --push .
```

> 说明：Dockerfile 已在**构建阶段**安装 `requirements-training.txt`（numpy/pyyaml/scipy/pytest），
> 生产阶段保持精简，仅保留 `requirements.txt` 运行时依赖。若只需本机构建，用 `docker build -t $IMAGE .`。

## 4. 推送到镜像仓库

### 4.1 Docker Hub

```bash
# 登录
docker login -u yourname

# 推送（若第 3 节用 --push 已推送可跳过）
docker push yourname/sampling-arm:2.1.0
docker push yourname/sampling-arm:latest
```

### 4.2 GitHub Container Registry (GHCR)

```bash
echo $CR_PAT | docker login ghcr.io -u <github-username> --password-stdin

export IMAGE=ghcr.io/<org>/sampling-arm:2.1.0
docker buildx build --platform linux/amd64,linux/arm64 -t $IMAGE --push .
```

### 4.3 私有 Harbor / 自建仓库

```bash
docker login <registry-host>:<port>
docker tag yourname/sampling-arm:2.1.0 <registry-host>/sampling-arm:2.1.0
docker push <registry-host>/sampling-arm:2.1.0
```

### 4.4 推送后校验

```bash
docker manifest inspect yourname/sampling-arm:2.1.0
# 应列出 amd64 与 arm64 两个平台条目
```

## 5. 生产环境部署（树莓派）

### 5.1 更新镜像引用

在 `docker-compose.yml`（或 `.env`）中指定新版本镜像：

```yaml
services:
  rpi-control:
    image: yourname/sampling-arm:2.1.0   # 改为新版本
    restart: unless-stopped
    # ... 原有 devices / volumes 配置不变
```

### 5.2 拉取并滚动更新

```bash
cd ~/zidongaixiangmu/rpi_control

# 拉取新镜像
docker pull yourname/sampling-arm:2.1.0

# 用新镜像重建容器（仅拉取新层，增量更新）
docker compose pull
docker compose up -d

# 查看是否已切换到新镜像
docker compose ps
docker inspect rpi-control-rpi-control-1 --format '{{.Image}}'
```

### 5.3 若需本地重新构建（离线/内网场景）

```bash
docker compose build --no-cache
docker compose up -d
```

## 7. 发布到 CI/CD 流水线

`.github/workflows/ci.yml` 已新增 `python-model-validation` 任务，每次 push/PR 自动执行：

1. **独立模型验证**：`python -m rpi_control.training.test_models`，5 项全 PASS。
2. **召回率门禁**：`monitor_recall --threshold 0.85`，召回率 < 0.85 使流水线失败（禁止部署）。
3. **告警自测**：以 0.90 阈值验证告警机制确实触发（失败被捕获为“OK: alert triggered”）。

### 7.1 本地 CI 等价验证结果（Round 13）

在本地环境复现了 CI 的关键门禁，结果全部通过：

| 门禁 | 命令 | 结果 |
|------|------|------|
| 独立模型验证（5 项） | `python -m rpi_control.training.test_models` | ✅ 全部 PASS（视觉/运动IK/安全/质量/碰撞） |
| 碰撞召回率门禁 | `monitor_recall --threshold 0.85` | ✅ 退出码 0，recall=0.8523 ≥ 0.85（PASS） |
| 告警触发自测 | `monitor_recall --threshold 0.90` | ✅ 退出码 1，正确触发 ALERT（证明门禁有效） |
| 单元测试（无硬件） | `pytest`（运动学/轨迹/抓取/坐标/Agent） | ✅ 184 passed, 6 skipped |

建议在通过 CI 后才执行第 3~5 节的推送与部署。

## 9. 常见问题排查

| 问题 | 原因 | 解决 |
|------|------|------|
| buildx 无 arm64 平台 | 模拟器未启用 | `docker run --privileged --rm tonistiigi/binfmt --install arm64` |
| 推送被拒 | 未登录/权限不足 | 执行 `docker login`，确认有写权限 |
| 树莓派拉取很慢 | 大镜像/网络差 | 改用私有内网仓库或局域网镜像加速 |
| 容器内 `collision_model.pkl` 缺 | 构建上下文未含 models | 确认镜像包含 `rpi_control/models/`（或在 CI 中先训练再构建） |
| 健康检查版本不符 | 旧容器未切换 | `docker compose pull && up -d`，确认 Image 为新标签 |
| 召回率门禁告警（退出码1） | 碰撞模型退化 | 禁止部署；重新训练并验证后再发布 |
