## 第 0 阶段：上电与连接检查（硬件）

- [ ] 接通机械臂主电源，确认各舵机/驱动器上电（无异常发热/异响）
- [ ] 确认 STM32 通过 USB-TTL 接到树莓派 GPIO UART（默认 `/dev/ttyAMA0` 或 `/dev/serial0`）
- [ ] 确认 OpenMV 接到树莓派 USB（默认 `/dev/ttyUSB0`）
- [ ] 确认树莓派网络已配置（静态 IP / 同一局域网，用于 Web 与云同步）

```bash
# 检查串口设备是否存在
ls -l /dev/ttyAMA0 /dev/serial0 /dev/ttyUSB0 2>/dev/null || echo "串口设备缺失，请检查接线"
# 确认树莓派串口未被 console 占用（/boot/config.txt 已注释 console=serial0）
```

## 第 3 阶段：启动模型服务与 Agent（Docker 方式）

> 模型与 Agent 以镜像内代码随容器启动，无需单独部署模型文件（构建阶段已包含 `models/*.pkl`）。

**需随服务启动的模型服务（5 个，均内置于镜像 `models/`）**：

| 模型服务 | 权重文件 | 加载方 | 作用 |
|----------|----------|--------|------|
| 运动学 IK 模型 | `motion_ik_model.pkl` | MotionAgent | IK 正/逆解与碰撞特征 |
| 安全模型 | `safety_model.pkl` | SafetyAgent | 安全风险评估 |
| 碰撞模型 | `collision_model.pkl` | Motion/SafetyAgent | 碰撞概率检测 |
| 质量评分模型 | `quality_model.pkl` | QualityAgent | 采样质量评分 |
| 视觉标定（非 ML） | `calibration`（settings.yaml） | VisionAgent | 像素→机器人坐标 |

- [ ] 构建/拉取镜像
- [ ] 确认镜像内含全部 `models/*.pkl`（见上表）
- [ ] 启动主服务（含 STM32/OpenMV 通信、机械臂、Web、云同步）
- [ ] 启动多 Agent 编排服务（加载全部 5 个 Agent）

## 第 4 阶段：Agent 与算法服务加载核验

所有 Agent 均继承 [base_agent.py](c:/Users/毕以恒/Desktop/zidongaixiangmu/rpi_control/agents/base_agent.py) 的 `BaseAgent.run()`，启动即自动执行 `check_constraints()` 护栏（不可擅自决策 / 不可不懂装懂 / 符合事实逻辑 / 常识性要求）。Round 14 起护栏升级为**递归扫描**（捕获嵌套 NaN/Inf）并新增 **PWM 物理范围校验**（500..2500 μs），输入与输出双端均校验。

| Agent | 文件 | 配置来源 | 启动即校验点 |
|-------|------|----------|--------------|
| Sampling | `agents/sampling_agent.py` | 默认 AgentConfig + `sampling_params.yaml` | 采样规划 |
| Vision | `agents/vision_agent.py` | 默认 AgentConfig + `settings.yaml` 标定 | 相机内参/外参加载、坐标往返 |
| Motion | `agents/motion_agent.py` | 默认 AgentConfig + `arm_params.yaml` | IK 模型加载、可达空间、碰撞常量、S3 动力学前馈可选启用 |
| Quality | `agents/quality_agent.py` | 默认 AgentConfig | 质量评分模型加载 |
| Safety | `agents/safety_agent.py` | 默认 AgentConfig + `safety` 配置 | 共享 `COLLISION_CLEARANCE_MM`、紧急停止 |

> 5 个 Agent 均由 [orchestrator.py](c:/Users/毕以恒/Desktop/zidongaixiangmu/rpi_control/agents/orchestrator.py) `_init_agents()` 实例化，逐一独立初始化、故障隔离，任一失败不影响其余 Agent。每个 Agent 最终经 `BaseAgent.run()` 执行，约束护栏对全部 5 个 Agent 自动生效，无绕过路径。

- [ ] 确认各 Agent 配置 `enabled: true`
- [ ] 确认 `config/settings.yaml` 中安全参数已启用（碰撞净空、急停阈值）
- [ ] 确认日志无 `Constraint violated` 异常（如有，说明护栏已拦截非法决策，需排查输入数据）
- [ ] 确认 4 个 ML 模型加载日志无 `Failed to initialize agent`（motion/safety 为关键 Agent，失败会 ERROR 日志）
- [ ] （S3 可选）如需启用动力学前馈：在调用 `DynamicFeedforwardController` 时设置 `use_inertia` 并按实际连杆质量更新 `DynamicParams`

```bash

curl -s http://<树莓派IP>:<port>/api/health
# 应返回 status=ok, stm32_connected=true, openmv_connected=true
```

## 第 7 阶段：故障排查速查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `stm32_connected=false` | 串口占用/接线/波特率不符 | `diagnose_stm32`，检查 `/dev/ttyAMA0` 与 config |
| `openmv_connected=false` | USB 未识别 | 检查 `/dev/ttyUSB0`，重启 OpenMV |
| 日志出现 `Constraint violated` | 输入/输出数据非法（NaN/越界/未授权） | 按报错字段定位来源 Agent 与数据链路 |
| 碰撞误报/漏报 | 模型未更新或边界配置不符 | 核对 `models/collision_model.pkl` 版本与 `COLLISION_CLEARANCE_MM` |
