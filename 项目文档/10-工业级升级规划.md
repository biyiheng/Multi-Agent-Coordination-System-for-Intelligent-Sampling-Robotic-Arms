## 0. 现状差距与升级总览

当前系统为**实验室原型**，在六个维度上与工业级标准存在明确差距。下表给出"现状 → 目标"的差距总览：

| 维度 | 现状 | 工业级目标 | 差距 |
|------|------|-----------|------|
| 硬件 | 纯开环舵机、无绝对编码器、STM32F103 | 绝对编码器闭环、谐波减速、STM32H7/安全协处理器 | 大 |
| 通信 | UART 115200bps、无校验 | CAN 1Mbps / EtherCAT、CRC+重发 | 大 |
| 控制算法 | S 曲线、10ms 周期、无动力学前馈 | 动力学前馈 + MPC、1ms 周期、动量观测器 | 大 |
| 视觉感知 | OpenMV 近程预处理 | 工业全局快门相机 + Jetson Orin + YOLO 6D 位姿 | 中-大 |
| 软件架构 | 单进程 Python、有限状态机 | ROS2 分布式、行为树、InfluxDB + AIOps | 大 |
| 安全体系 | 无功能安全认证 | ISO 13849 PLr d、双通道急停、安全协处理器 | 大 |

**总体策略**：采用"基础夯实 → 智能拓展 → 认证固化"三阶段渐进式重构，每阶段设置明确验收里程碑，避免一次性大爆炸式改造带来的高风险。

## 1. 硬件层面重构

### 1.1 现状
- 纯开环舵机控制（PWM 位置指令，无末端/关节位置反馈回路）
- 主控 STM32F103C8T6，资源与算力受限
- 存在传动间隙与温度漂移，无法保证 ±0.1mm 绝对精度

### 1.2 目标架构
```
STM32H7 (安全/运动主控)
   ├── 6× 绝对值编码器 (AS5048, SPI) → 关节闭环反馈
   ├── 谐波减速模组 (消除背隙/温度漂移)
   ├── 安全协处理器 (独立看门狗/急停逻辑)
   └── CAN 控制器 (通信升级)
```

### 1.3 实施要点
- **关节闭环**：在每关节输出轴加装 AS5048 高精度绝对值编码器（14bit、±0.09° 分辨率），MCU 内闭环 PID/级联环，用编码器读数替代开环 PWM 假设位置。
- **谐波减速**：逐步引入谐波减速模组，消除传动间隙、提高刚度、降低温度漂移对精度的影响。
- **主控升级**：STM32F103 → STM32H7（Cortex-M7 @ 480MHz，硬件 FPU/DSP，充足外设），或配备独立安全监控协处理器（如 TPS65381 / 安全 MCU）实现硬件冗余。
- **验收里程碑（短期）**：单关节定位误差 ≤ 0.01°、重复定位精度 ≤ 0.05mm、闭环带宽 ≥ 20Hz。

## 2. 通信层面重构

### 2.1 现状
- UART 115200bps，无 CRC，无确定性与多节点同步机制
- 单主-从拓扑，抖动大，无法支撑多节点高同步

### 2.2 目标架构
```
CAN 总线 (1Mbps) / EtherCAT 工业以太网
   ├── 确定性调度 (CAN 优先级仲裁 / EtherCAT DC 时钟同步)
   ├── CRC32 校验 + 超时重发机制
   ├── 多节点同步 (多关节/传感器/视觉/安全节点)
   └── 帧 ID 优先级映射 (急停帧最高优先级)
```

### 2.3 实施要点
- **总线移植**：将关键控制/安全帧迁移至 CAN（1Mbps），保留 UART 作为诊断/低速通道。
- **数据完整性**：引入 CRC32 校验与重发（带重发次数上限与超时），杜绝静默损坏数据。
- **确定性**：EtherCAT 提供 DC 分布式时钟实现节点同步抖动 < 1µs；CAN 用标识符仲裁保证关键帧低延迟。
- **验收里程碑（短期）**：1kHz 周期抖动 < 100µs、坏帧可检出并重发、链路中断 < 100ms 内触发安全停车。

## 3. 控制算法层面重构

### 3.1 现状
- S 曲线 / 梯形速度规划，纯运动学、无动力学模型
- 控制周期 10ms
- 无碰撞检测与柔顺力控（力控为算法层原型）

### 3.2 目标架构
```
高频轨迹优化 (MPC, 1ms 周期)
   ├── 动力学前馈：重力补偿 + 关节摩擦力模型
   ├── 动量观测器：实时碰撞检测
   ├── 阻抗/力位混合控制：柔顺力控
   └── 绝对值编码器闭环 (见 §1)
```

### 3.3 实施要点
- **动力学前馈**：辨识连杆质量/质心/惯性张量，构建重力项 G(q) 与摩擦力项 F(q̇)，前馈补偿提升低速精度。
- **MPC 高频轨迹优化**：将控制周期从 10ms 压缩至 1ms，基于动力学模型做预测与约束优化，兼顾精度与平滑。
- **动量观测器**：基于广义动量残差检测外部接触力，实现灵敏碰撞检测（无需额外传感器）。
- **柔顺力控**：完善阻抗控制与力位混合控制，支持轴孔装配等任务。
- **验收里程碑（中期）**：轨迹跟踪误差 ≤ 0.5mm、碰撞检测响应 < 5ms、力控稳态误差 ≤ 0.5N。

## 4. 视觉感知层面重构

### 4.1 现状
- OpenMV 作为近程预处理（AprilTag/颜色识别、坐标变换）
- 光照/遮挡鲁棒性有限，无 6D 位姿与缺陷检测

### 4.2 目标架构
```
工业全局快门相机
   ├── Jetson Orin 边缘计算平台
   │     ├── YOLO 目标检测/6D 位姿估计
   │     ├── 缺陷检测 (分割/分类)
   │     └── 手眼标定 + 在线畸变校正
   └── OpenMV (保留为近程/低速预处理)
```

### 4.3 实施要点
- **近程**：保留 OpenMV 做近程/触发预处理，降低主链路负载。
- **中程/远程**：替换为全局快门工业相机（消除卷帘畸变），搭载 Jetson Orin 运行 YOLO 等 DL 模型，实现复杂光照与遮挡下的 6D 位姿估计与缺陷检测。
- **标定链路**：完善手眼标定（eye-in-hand / eye-to-hand），引入在线畸变校正（针对镜头温度/机械变形导致的标定漂移）。
- **验收里程碑（中期）**：6D 位姿估计精度 ≤ 1mm/1°，遮挡场景检出率 ≥ 95%，标定重投影误差 < 1px。

## 5. 软件架构层面重构

### 5.1 现状
- 单进程 Python（asyncio），多 Agent 为进程内模块
- 有限状态机驱动的任务编排
- 无时序数据库与运维可观测性

### 5.2 目标架构
```
ROS2 分布式框架
   ├── 行为树 (BehaviorTree.CPP) 替代有限状态机
   ├── 多 Agent 决策 + 故障恢复
   ├── InfluxDB 时序库：传感器/状态遥测
   ├── AIOps：预测性维护 + 链路追踪 (OpenTelemetry)
   └── Docker 容器化部署 (现有基础保留)
```

### 5.3 实施要点
- **ROS2 迁移**：将运动/视觉/采样等模块逐步拆分为 ROS2 节点，节点间用话题/服务/动作通信，支持分布式与热更新。
- **行为树替代 FSM**：以行为树表达任务流与故障恢复策略，提升决策鲁棒性与可维护性（节点化、可组合、易回退）。
- **可观测性**：接入 InfluxDB 存储时序遥测，集成 OpenTelemetry 做链路追踪，结合 AIOps 做异常检测与预测性维护。
- **验收里程碑（中期/长期）**：节点可在 5s 内热重启、故障恢复策略 ≥ 90% 场景有效、遥测写入延迟 < 50ms。

## 6. 安全体系与认证

### 6.1 现状
- 软件层有急停/限位/速度监控（[realtime_safety.py](c:/Users/毕以恒/Desktop/zidongaixiangmu/rpi_control/safety/realtime_safety.py)、[safety_agent.py](c:/Users/毕以恒/Desktop/zidongaixiangmu/rpi_control/agents/safety_agent.py)）
- 无硬件冗余、无功能安全认证

### 6.2 目标架构（ISO 13849 PLr d）
```
双通道急停回路
   ├── 独立安全监控协处理器
   ├── 安全继电器 (硬线冗余切断动力)
   ├── 硬件 + 软件双重冗余
   └── IP54+ 防护 (防尘防溅)
```

### 6.3 实施要点
- **硬件安全**：增设双通道急停回路、独立安全监控协处理器与安全继电器，实现动力硬线冗余切断（即使主控失效也能停车）。
- **软件安全**：现有安全 Agent / 实时安全模块升级为符合 PLr d 的软件安全功能，与硬件冗余互为备份。
- **认证路径**：开展 CE 认证与功能安全认证（ISO 13849 / IEC 62061），编制风险评估（ISO 12100）与验证报告。
- **环境防护**：整机防护提升至 IP54+，应对粉尘与液体飞溅的工业现场。
- **验收里程碑（长期）**：通过 CE 与功能安全评估，SIL/PL 等级达标，急停回路响应 < 30ms。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 谐波减速/编码器采购与集成周期长 | 阶段一延期 | 先以增量编码器闭环验证，减速模组并行推进 |
| CAN 移植与现有 UART 协议并存 | 协议兼容风险 | 短期双栈并存，逐步切换，保留 UART 诊断通道 |
| 1ms 控制周期对主控算力要求高 | 实时性不足 | 硬件 FPU/DSP + 确定性调度，必要时分割控制任务 |
| ROS2 迁移破坏已验证功能 | 回归风险 | 新分支 + 现有 test_models/单测作为回归基线 |
| 功能安全认证周期与成本高 | 长期延期 | 提前引入安全设计规范，分步取证 |
