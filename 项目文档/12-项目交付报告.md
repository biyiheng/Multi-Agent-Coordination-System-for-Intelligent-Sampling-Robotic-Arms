## 3. 约束生效证明（不可擅自决策 / 符合事实逻辑）

框架级护栏 `BaseAgent.check_constraints()` 在 `BaseAgent.run()` 中对**输入**与**输出**双端调用，共四条款：

| 条款 | 校验内容 | 证明 |
|------|----------|------|
| 不可擅自决策 | `authorization_required` 且无 `authorization` 时拒绝 | 按需启用的安全网 |
| 不可不懂装懂 | 存在 `assumed`/`unverified_assumptions` 时拒绝 | 按需启用 |
| 符合事实逻辑 | 递归扫描 NaN/Inf（含嵌套 dict/list） | 始终生效 |
| 常识性要求 | 关节角 ±360°；PWM 500..2500 μs | 始终生效 |

**端到端证明（实测）**：
```
YAML OK: arm_params / sampling_params / settings
Agents loaded: ['motion','quality','safety','sampling','vision']
Init errors: {}
GUARDRAIL: all 5 agents are BaseAgent subclasses -> run() applies
```
- 5 个 Agent 均为 `BaseAgent` 子类，统一经 `run()` 执行，**无绕过路径**。
- orchestrator 为纯协调器，其状态处理器最终均经 `agent.run()` 调用。

## 5. 一键启动脚本使用说明

```bash
./start_all.sh --check    # 环境/模型/约束自检
./start_all.sh            # 本地源码方式启动全部 5 Agent + 模型服务
./start_all.sh --docker   # docker compose 方式启动
./start_all.sh --stop     # 停止
./start_all.sh --log      # 跟随日志
```

脚本 `do_check` 会校验：依赖、4 个 ML 模型存在性、5 个 Agent 加载无错误、护栏生效；随后后台启动 `main.py`（主服务）与 `Orchestrator`（加载全部 Agent）。

## 6. 后续维护建议

1. **版本基线**：保留已交付验证的 v2.4.0 基线；S4/M/L 工业级升级在**并行新分支**推进，避免回归。
2. **模型重训**：任何训练逻辑变更后运行 `python -m rpi_control.training.retrain_all`，并执行 `test_models.py` 独立验证，召回率门禁 ≥0.85。
3. **硬件更换后**：重做相机/手眼标定、机械臂零位校准；编码器加装后做零位标定（见 11-硬件采购清单 §2.1）。
4. **CAN/编码器验收**：心跳 1kHz 抖动 <100µs、坏帧可检出重发、编码器角度单调稳定（11 文档 §2.3/§3.4）。
5. **日志与监控**：关注 `Constraint violated` 日志——出现即表明护栏拦截非法决策，需排查输入数据而非关停护栏。
6. **安全认证**（长期）：推进 ISO 13849 PLr d 双通道急停 + IP54，编制 ISO 12100 风险评估。
7. **一键启动脚本**：建议纳入 systemd 或 cron 自启；部署机为 Linux（RPi），脚本依赖 bash。
8. **多端互通安全**：生产环境启用 HTTPS（反向代理终止 TLS）并收紧 CORS；WiFi 凭据已加密存储（AES-256-GCM），勿明文记录在日志。
9. **App 维护**：`flutter analyze` 保持 0 error；升级 Flutter 后重新 `flutter build` 验证 Android/iOS 双端。
10. **ESP32 模块**：生产部署后核对 AT 固件版本与波特率（115200），无响应时依据超时回归测试日志定位。
