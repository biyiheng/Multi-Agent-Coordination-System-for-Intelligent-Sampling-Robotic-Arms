## 1. 测试目标与范围

### 1.1 目标
在模拟的极端工况下，验证以下**工业级安全约束**是否可靠生效：

1. **急停优先级**：急停帧在 CAN 总线仲裁中具有最高优先级，且任何危险条件（心跳丢失、关节越限、碰撞、力矩过载）都能**可靠升级为实际急停**（含 2026-08-10 修复的 DANGER→ESTOP 升级链路）。
2. **坏帧处理**：CRC 校验能检出并丢弃损坏/伪造帧，不污染控制数据；坏帧率升高时系统仍能安全降级而非失控。
3. **数值鲁棒性**：动态前馈在 NaN/Inf 输入下不传播异常、不污染滤波器状态。
4. **极端工况鲁棒性**：高负载、超温、双网丢失、总线风暴等场景下系统仍处于受控状态。

### 1.2 测试范围
| 层级 | 对象 | 测试方式 |
|------|------|----------|
| 软件层（树莓派） | `safety_agent.py`、`realtime_safety.py`、`dynamic_feedforward.py` | Python 单测 + 仿真注入 |
| 固件层（STM32F103） | `y_can.c`（CRC/重发/急停帧）、`y_encoder.c`（磁场/错误计数） | 硬件在环 + 总线注入 |
| 通信层 | CAN 帧 ID 优先级映射、坏帧注入 | CAN 总线回环 + 伪造帧注入 |

- **注入工具**：

  - 负载注入：`stress-ng` / 高频率控制循环模拟 CPU 满载。

## 3. 测试用例矩阵

### 3.1 急停优先级（ESTOP Priority）

| 编号 | 场景 | 注入 | 期望行为 | 通过标准 |
|------|------|------|----------|----------|
| ES-01 | 正常状态运行 | 无 | 不触发急停 | `estop_triggered=false` |
| ES-02 | 关节越限 → 急停 | `joint_1=500°` | 触发急停，状态→ESTOP | `safety_state=="estop"`，急停帧已发 |
| ES-03 | 心跳丢失 → 急停 | `stm32_last_heartbeat=0` | 心跳超时→DANGER→急停 | 心跳超时 2000ms 内触发 |
| ES-04 | 碰撞危险 → 急停 | 路径贴近障碍(净空<0) | 触发急停 | 状态→ESTOP |
| ES-05 | 力矩过载 → 急停 | 关节力矩超限 | 触发急停 | 状态→ESTOP |
| ES-06 | 总线急停帧最高优先级 | 同时注入急停帧 + 高流量关节帧 | 急停帧先于普通帧被仲裁接收 | CAN 分析仪显示急停帧 ID 最低 |
| ES-07 | 急停防抖/幂等 | 连续触发急停 | 仅首次执行实际停机动作用 | `_estop_active` 去重，无重复下发 |

**回归验证**：ES-02~05 对应 [test_agents.py](c:/Users/毕以恒/Desktop/zidongaixiangmu/rpi_control/tests/test_agents.py) 新增的 `TestSafetyAgentEscalation`（DANGER→ESTOP 修复）。

### 3.2 坏帧处理（Bad Frame Handling）

| 编号 | 场景 | 注入 | 期望行为 | 通过标准 |
|------|------|------|----------|----------|
| BF-01 | CRC 错误帧 | 篡改帧负载字节，保持 DLC | 帧被丢弃并计数 | `rx_crc_fail` 递增，`can_receive` 返回 CRC 错误 |
| BF-02 | 错误 DLC | 发送 DLC<2 或 DLC>8 帧 | 帧被拒绝 | 不进入数据处理 |
| BF-03 | 伪造高优先级帧 | 注入 `CAN_TYPE_EMERG` 伪造急停 | 接收端仅按真实事件响应 | 无伪造急停造成的误停（软件层二次确认） |
| BF-04 | 坏帧风暴 | 按 1kHz 注入 30% 坏帧 | 正常帧仍被可靠接收，无死锁 | 正常帧 CRC 通过率 100%，系统不失控 |
| BF-05 | 静默丢帧 | 随机丢弃 10% 帧 | 上层心跳/顺序校验检出 | 触发通信超时告警而非错误执行 |
| BF-06 | 重发上限 | 发送持续失败 | 达到 `CAN_MAX_RETRY=3` 后放弃 | 返回 `CAN_ERR_TIMEOUT`，不无限阻塞 |

### 3.3 数值鲁棒性（动态前馈）

| 编号 | 场景 | 注入 | 期望行为 | 通过标准 |
|------|------|------|----------|----------|
| NF-01 | NaN 输入 | `q=[nan,...]` | 返回零前馈，不抛异常 | 无异常，输出全 0 |
| NF-02 | Inf 输入 | `q_dot=[inf,...]` | 返回零前馈 | 无异常，输出全 0 |
| NF-03 | 滤波污染 | NaN 后接正常输入 | 滤波器被重置，不传播 NaN | `compute_smoothed` 二次调用输出有限 |
| NF-04 | 力矩限幅 | 大加速度输入 | 输出被限幅 | 各元素 ≤ 限幅值 |

### 3.4 极端工况鲁棒性

| 编号 | 场景 | 注入 | 期望行为 | 通过标准 |
|------|------|------|----------|----------|
| EX-01 | 双网丢失 | `set_network_status(False,False)` | 触发通信超时事件 | 状态→DANGER→急停 |
| EX-02 | 高负载 | 满载并发控制循环 | 控制周期仍受控 | 周期超时 < 90% 占比，不失控 |
| EX-03 | 时钟漂移 | `sync_clock` 注入 200ppm 漂移 | 触发漂移告警 | `CLOCK_DRIFT` 事件产生 |
| EX-04 | 温度/过载组合 | 超温 + 力矩过载同时 | 最高严重级事件主导状态 | 状态为急停/保护性停止 |
| EX-05 | 长时间运行 | 8h 连续 + 随机故障注入 | 无内存泄漏、无状态漂移 | 事件计数单调，状态可恢复 |

## 4. 测试脚本

### 4.1 软件层回归（可自动执行）
```bash
# 安全 Agent 急停升级回归（含新增护栏测试）
python -m pytest rpi_control/tests/test_agents.py -q

# 动态前馈数值鲁棒性
python -m pytest rpi_control/tests/test_dynamic_feedforward.py -q

# H7 闭环（编码器+CAN 仿真）
python -m pytest rpi_control/tests/test_h7_closed_loop.py -q
```

### 4.2 坏帧注入示例（固件层，Python 调用 CAN 分析仪）
```python
# 伪代码：通过 python-can 向 STM32 注入篡改帧
import can
bus = can.interface.Bus(channel='can0', bustype='socketcan')
# 发送 CRC 错误的帧（篡改负载后 CRC 不匹配）
msg = can.Message(arbitration_id=0x1020, data=[0xAA]*7, is_extended_id=False)
bus.send(msg)
# 注入伪造急停帧
emg = can.Message(arbitration_id=0x0F00, data=[0x00], is_extended_id=False)
bus.send(emg)
```

### 4.3 急停优先级验证（总线观察）
使用 CAN 分析仪抓取总线，确认在注入急停帧 `0x0F00` 与普通关节帧 `0x1000~0x100F` 同时竞争时，急停帧始终先被仲裁传输（ID 越小优先级越高）。

> 注：帧 ID 编码 `(prio<<12)|(type<<8)|node_id`，急停 prio=0x00 → ID=0x0F00，低于所有关节(0x10…)/传感器(0x20…)/视觉(0x30…)帧，满足"急停最高优先级"。

## 5. 测试执行与报告

1. **执行顺序**：先软件层回归（§4.1）→ 再固件/总线注入（§4.2/4.3）→ 最后极端工况长跑（§3.4）。
2. **判定标准**：所有用例通过；坏帧风暴下正常帧 CRC 通过率 100%；急停从检测到下发 < 10ms（`realtime_safety.FAULT_RESPONSE_DEADLINE_S`）。
3. **报告**：每轮测试结果写入 `reports/stress_test_results.json`（含用例编号、通过/失败、耗时、关键指标）。
4. **失败处理**：按 [03-安全性文档.md](c:/Users/毕以恒/Desktop/zidongaixiangmu/项目文档/03-安全性文档.md) 风险矩阵登记，并回填本方案与升级规划。
