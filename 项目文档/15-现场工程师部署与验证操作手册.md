## 1. 本手册用途

本手册为现场工程师提供**部署前最后一步**的操作指引，覆盖：

1. 本批次**安全逻辑修复**（DANGER→ESTOP 升级、COMMUNICATION_TIMEOUT 状态转移）与新增的**日志埋点**，及如何通过日志定位异常。
2. **自动化压力测试脚本**的打包与运行方式。
3. 压力测试报告/日志的**判定标准与排查指引**。

---

## 2. 本批次安全逻辑修复清单

| 修复 | 位置 | 现象（修复前） | 修复后行为 |
|------|------|----------------|------------|
| DANGER→ESTOP 升级 | `agents/safety_agent.py` `process()` | 检测到心跳丢失/关节越限/碰撞等危险，只置 DANGER，**从不真正停车** | 危险条件自动升级为 ESTOP 并下发急停 |
| COMMUNICATION_TIMEOUT 状态转移 | `safety/realtime_safety.py` `_update_safety_state()` | 双网丢失后 `is_safe_to_operate()` 仍返回 True，系统继续运行 | 通信超时/越限/越界/掉电 → `PROTECTIVE_STOP`，硬件故障 → `FAULT` |
| 急停详细报警 | `safety_agent.py` `emergency_stop(reason)` | 只输出笼统 "EMERGENCY STOP TRIGGERED!" | 输出具体触发原因（见 §3） |
| 状态转移日志埋点 | `realtime_safety.py` | 无状态变化日志 | 输出转移前后状态、触发事件、网络状态（见 §3） |

## 3. 日志埋点与现场排查

### 3.1 急停原因日志（SafetyAgent）
危险条件触发急停时，日志包含具体原因，可按关键词定位：
```
CRITICAL EMERGENCY STOP TRIGGERED! reason: joint_limits violation: joint_2 over_max value=500.0 limit=130.0
CRITICAL EMERGENCY STOP TRIGGERED! reason: heartbeat loss (age=5000ms > timeout=2000ms)
CRITICAL EMERGENCY STOP TRIGGERED! reason: collision danger: obstacle=pillar dist=0.0mm min_safe=80.0mm
```

### 3.2 双网丢失状态转移日志（RealTimeSafetyController）
```
ERROR    realtime_safety Safety: BOTH networks lost (primary=LOST backup=LOST) -> emitting COMMUNICATION_TIMEOUT critical event
WARNING  realtime_safety Safety: state transition normal -> protective_stop | trigger=communication_timeout severity=2 | desc=Both primary and backup networks lost | network: primary=LOST backup=LOST | critical_events=1
```
- `trigger=communication_timeout`：触发转移的事件类型。
- `network: primary=LOST backup=LOST`：双网丢失直接反映在日志中，便于确认故障根因。
- `critical_events=1`：本次进入状态机评估的严重事件数。

## 4. 压力测试脚本打包与运行

### 4.1 脚本清单
| 文件 | 作用 |
|------|------|
| `rpi_control/tests/stress_test_extreme.py` | 自动化极端工况压力测试（16 用例） |
| `rpi_control/tests/test_agents.py` | Agent 急停升级回归（含本批次新增护栏） |
| `rpi_control/tests/test_dynamic_feedforward.py` | 动态前馈数值鲁棒性 |

### 4.2 运行方式（两种）

**方式 A — 完整 pytest（推荐，覆盖全部 16 用例）**
```bash
cd 项目根目录
python -m pytest rpi_control/tests/stress_test_extreme.py -q
```

**方式 B — 直接运行并生成 JSON 报告**
```bash
python rpi_control/tests/stress_test_extreme.py
```
报告写入：`reports/stress_test_results.json`。

### 4.3 测试覆盖
| 分组 | 用例 | 覆盖点 |
|------|------|--------|
| 急停升级 | 关节越限/心跳丢失/碰撞/正常 | DANGER→ESTOP 可靠升级 |
| CAN 坏帧 | 篡改 CRC/负载/非法 DLC | 坏帧被丢弃 |
| CAN 丢包 | 30% 丢包 | 正常帧 100% 通过，无死锁 |
| 极端工况 | 双网丢失/碰撞力矩/力限制/长跑 | 状态受控，无漂移 |
| 数值鲁棒 | NaN/Inf 输入 | 返回零，滤波器不污染 |

## 5. 现场部署验证步骤

```bash
# 1) 环境自检（模型/依赖/Agent）
./start_all.sh --check

# 2) 压力测试（部署前最后一步）
python -m pytest rpi_control/tests/stress_test_extreme.py -q

# 3) 启动系统
./start_all.sh
```

**判定标准（全部满足视为通过）**：
- 压力测试全部用例 **PASS**（预期 16 passed）。
- 双网丢失场景下，日志出现 `state transition normal -> protective_stop | trigger=communication_timeout`。
- 危险条件（越限/心跳/碰撞）下，日志出现 `EMERGENCY STOP TRIGGERED! reason: ...`。
- 系统在无危险时**不误触发**急停。

## 6. 报告解读

`reports/stress_test_results.json` 字段：
| 字段 | 含义 |
|------|------|
| `suite` | 套件名 `extreme_condition_stress` |
| `timestamp` | 运行时间 |
| `results` | 各用例 → `"pass"` |
| `note` | 覆盖范围说明 |

若 `results` 中出现失败用例，按对应分组排查：
- 急停升级失败 → 检查 `safety_agent.py` 状态机与 `_update_safety_state`。
- CAN 坏帧失败 → 检查固件 `y_can.c` 的 CRC/DLC 校验与帧组包。
- 极端工况失败 → 检查 `realtime_safety.py` 事件映射与网络状态。

## 7. 常见问题（FAQ）

| 现象 | 处理 |
|------|------|
| 终端显示 JSON 中文乱码 | PowerShell 显示编码问题，文件本身为 UTF-8，用 `Get-Content -Encoding UTF8` 查看 |
| 直接运行脚本报 `ModuleNotFoundError: rpi_control` | 脚本已内置 `sys.path` 修复，确认从项目根目录执行 |
| 未看到状态转移日志 | 需在应用入口配置 `logging` 级别 ≥ WARNING（如 `logging.basicConfig(level=logging.WARNING)`） |
| 压测通过但部署后急停不触发 | 确认 `start_all.sh --check` 的 Agent 约束自检通过，模型就绪 |
