## 1. 日志位置与等级说明

| 日志来源 | 模块 | 关键等级 |
|----------|------|----------|
| 急停触发 | `rpi_control.agents.safety_agent` | `CRITICAL`(50) |
| 状态转移/双网丢失 | `realtime_safety` | `ERROR`/`WARNING` |
| 动态前馈非有限输入 | `motion.dynamic_feedforward` | `ERROR` |

> 现场查看日志需将日志级别配置到 `WARNING` 及以上：
> `logging.basicConfig(level=logging.WARNING)`。

## 2. COMMUNICATION_TIMEOUT（双网丢失 / 通信超时）

### 2.1 日志特征
```
ERROR   realtime_safety Safety: BOTH networks lost (primary=LOST backup=LOST) -> emitting COMMUNICATION_TIMEOUT critical event
WARNING realtime_safety Safety: state transition normal -> protective_stop | trigger=communication_timeout severity=2 | desc=Both primary and backup networks lost | network: primary=LOST backup=LOST | critical_events=1
```

### 2.2 关键字段解读
| 字段 | 含义 | 排查动作 |
|------|------|----------|
| `BOTH networks lost` | 主备双网同时断开 | 检查主/备网卡、交换机、线缆 |
| `trigger=communication_timeout` | 触发本次转移的事件 | 确认是否为真实通信故障 |
| `network: primary=LOST backup=LOST` | 当前网络状态 | 定位是单网还是双网 |
| `critical_events=1` | 进入评估的严重事件数 | 数量骤增提示故障风暴 |
| `protective_stop` | 系统已安全停车 | 符合预期；恢复前勿操作 |

### 2.3 处理步骤
1. **确认故障范围**：查看 `network:` 字段，判断单网/双网。
2. **物理排查**：网线/交换机/接口/供电，主备链路逐段 ping。
3. **恢复链路**：网络恢复后，等待 `critical_events` 清零（超 100ms 无严重事件）。
4. **确认自动恢复**：日志出现 `INFO auto-recover protective_stop -> NORMAL`。
5. **若未自动恢复**：检查 `set_network_status(True, True)` 是否被调用恢复标志。

## 3. 急停触发（EMERGENCY STOP）

### 3.1 日志特征
```
CRITICAL EMERGENCY STOP TRIGGERED! reason: <具体原因>
CRITICAL ESTOP command sent to STM32
```

### 3.2 常见 `reason` 与处理
| reason 特征 | 含义 | 处理步骤 |
|-------------|------|----------|
| `joint_limits violation: <joint> over_max/under_min value=.. limit=..` | 关节越限 | 检查目标位姿/关节零点/限位参数 |
| `heartbeat loss (age=..ms > timeout=..ms)` | 与 STM32 心跳失联 | 检查 UART/CAN 连线、固件心跳发送 |
| `collision danger: obstacle=.. dist=..mm min_safe=..mm` | 路径贴近障碍 | 检查障碍物坐标/半径配置，确认净空 |
| `workspace violation: <axis> over_max value=..` | 末端出工作区 | 检查采样点是否在工作区内 |

### 3.3 处理步骤
1. **定位原因**：读取 `reason:` 字段，确定触发类别（越限/心跳/碰撞/工作区）。
2. **安全处理**：确认人员安全后，处理对应根因（调参/接线/清障）。
3. **解除急停**：调用 `recover_from_safety_event()`（需操作员确认）。
4. **验证**：运行压力测试急停用例确认不再误触发。

## 4. 状态转移速查

| 触发事件 | 目标状态 | 是否自动恢复 |
|----------|----------|--------------|
| `ESTOP_PRESSED` | `EMERGENCY_STOP` | 需手动恢复 |
| `SAFEGUARD_OPEN` | `SAFEGUARD_STOP` | 关安全门后恢复 |
| `COLLISION_DETECTED` / `TORQUE_OVERLOAD` / `FORCE_LIMIT_EXCEEDED` | `PROTECTIVE_STOP` | 超 100ms 无事件自动恢复 |
| `COMMUNICATION_TIMEOUT` / `JOINT_LIMIT_VIOLATION` / `WORKSPACE_VIOLATION` / `POWER_LOSS` | `PROTECTIVE_STOP` | 超 100ms 无事件自动恢复 |
| `HARDWARE_FAULT` | `FAULT` | 需人工处理 |
| `SPEED_LIMIT_EXCEEDED` | `REDUCED_SPEED` | 自动 |

## 5. 一键验证入口

```bash
# 部署前一键压力验证（运行压力测试并生成报告）
./start_all.sh --stress

# 环境自检
./start_all.sh --check
```

报告输出：`reports/stress_test_results.json`。

## 6. 常见故障定位速查

| 现象 | 日志线索 | 根因方向 |
|------|----------|----------|
| 系统运行中未停车 | 无 `state transition` 日志 | 事件映射/日志级别不足 |
| 急停不触发 | 无 `EMERGENCY STOP` 日志 | Agent 状态机/约束护栏 |
| 报告中文乱码 | — | PowerShell 显示编码，用 `-Encoding UTF8` 查看 |
| 压测直接运行报模块缺失 | `ModuleNotFoundError: rpi_control` | 未在项目根目录运行 |
