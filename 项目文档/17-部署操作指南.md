## 1. 部署前检查清单

| 项 | 要求 |
|----|------|
| Python | 3.11+ |
| 硬件 | 树莓派 + STM32F103 + OpenMV（可选 Jetson） |
| 网络 | 主/备份双网（用于安全监控） |
| 依赖 | `pip install -r rpi_control/requirements.txt` |
| 模型 | 4 个 ML 模型已就绪（`motion_ik/safety/collision/quality .pkl`） |

---

## 2. 快速安装

```bash
# 1) 进入项目根目录
cd Multi-Agent-Coordination-System-for-Intelligent-Sampling-Robotic-Arms

# 2) 安装 Python 依赖
pip install -r rpi_control/requirements.txt

# 3) （可选）固件烧录：STM32F103
cd stm32_firmware && make all && make flash   # 需要 ST-Link + arm-none-eabi 工具链
```

---

## 3. 一键启动（推荐）

使用根目录 `start_all.sh`（真实 Linux 环境）：

```bash
./start_all.sh --check     # ① 环境/模型/约束自检（不启动）
./start_all.sh --stress    # ② 压力测试 + 生成报告（部署前必做）
./start_all.sh             # ③ 启动全部 5 个 Agent + 模型服务
./start_all.sh --log       # 跟随主服务与编排器日志
./start_all.sh --stop      # 停止所有服务
```

> **首次部署建议顺序**：`--check` → `--stress` → 启动 → 访问健康检查。

---

## 4. 启动后验证

```bash
# 健康检查
curl http://<设备IP>:8000/api/health

# 查看进程与 PID
ls .run/            # main.pid / orch.pid
tail -f .run/main.log
```

各 Agent 经 `BaseAgent.run()` 启动，约束护栏（不可擅自决策 / 符合事实逻辑）自动生效。

## 5. 可选部署方式

### 5.1 Docker
```bash
docker compose -f rpi_control/docker-compose.yml up -d
```

### 5.2 ROS2 / Jetson（工业级升级）
```bash
./start_all.sh --ros2            # 以 ROS2 节点方式启动 Agent（需已装 ROS2）
./start_all.sh --jetson          # 额外启动 Jetson 视觉节点
./start_all.sh --ros2 --jetson   # 组合
```
> 未检测到对应环境时脚本会自动回退到本地源码方式，不影响启动。

### 5.3 systemd 服务
```bash
# 安装服务（脚本路径：rpi_control/scripts/rpi-sampling-arm.service）
sudo cp rpi_control/scripts/rpi-sampling-arm.service /etc/systemd/system/
sudo systemctl enable --now rpi-sampling-arm
```

## 6. 常见问题快速定位

| 现象 | 处理 |
|------|------|
| `--check` 报模型缺失 | 先完成训练/复制模型到 `models/`，再重跑 |
| 启动后无健康响应 | 查看 `logs/` 与 `.run/main.log`，确认 8000 端口未被占用 |
| 急停误触发 | 按 [16-故障排查速查表](16-故障排查速查表.md) 中"急停触发"章节定位 |
| 双网丢失告警 | 检查主/备网络物理连接，见速查表"COMMUNICATION_TIMEOUT"章节 |
| 压力测试失败 | 依据 `reports/stress_test_results.json` 定位，参考 [13-压力测试方案](13-压力测试方案.md) |
